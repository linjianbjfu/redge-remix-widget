# Agent Note: 原生会话的独立用途与历史数据隔离

Status: implemented

## 问题

原生 JavaScript Widget 与网页三文件产物拥有不同的输入、工具和发布语义。两条业务共用用户 DO、SQLite、pi 会话构造与 Hub，不能依据路径名或客户端声明把同一个会话切换成另一种业务。删除原生运行路径后，已有原生会话仍可能留在同一个数据库中。

## 决策

session 的用途不可变，旧的无用途网页记录默认归为 `webclip`。原生记录使用独立用途，不在网页列表中出现，也不能从网页接口读取、提交、订阅、中止或删除。网页 alarm 只处理网页 turn；原生记录不受网页 24 小时幂等清理影响。源码删除与存量隔离由[仅保留网页生成](../../implemented/simplification/2026-11-05-web-generation-only.md)拥有，当前工程没有原生生成 API 或 iOS 运行时。

原生历史的产物是单文件不可变源码版本，与 `extra.js`、`widget.html` 和 `meta.json` 没有互换关系。原生公开历史是用户、助手正文、结果引用和终态的投影；内部 pi 条目包含工具参数与上下文，不是直接展示给用户的正文。已有记录不能由网页生成器恢复或重新发布。

历史版本对应成功 turn 的原子提交。原生的完整源码提交只暂存候选，成功终态才发布最后一个有效候选；失败、取消与旧 attempt 不覆盖先前版本。原始 turnId 与执行 attempt 的职责不同，后者阻止取消、删除和恢复后的迟到回调提交。保留这些记录的含义，避免未来数据维护把中间候选或旧 attempt 当作最终产物。

原生生成的设计依据是服务端拥有历史、完整源码与模型执行，不依赖手机在线；独立 SDK 教材和按需参考使模型能够使用自定义 Swift API，不能用宽松类型声明推断未定义能力。服务端语法检查不能证明 SwiftUI、JavaScriptCore、硬件权限和 WidgetKit 运行正确。历史原生运行时与客户端采用、缓存的取舍保存在[原生运行时快照](../../archived/feature/2026-10-19-widgee-ios-native-runtime.md)及[资料库快照](../../archived/feature/2026-10-19-widgee-tabbed-chat-library-ux.md)，它们不是当前功能说明。

## 曾考虑的替代方案

**给网页接口增加产物类型。** 两条业务的输入、工具和产物不同；独立用途保护网页协议，共享底层构造即可。

**从聊天 Markdown 或工作区文件交付原生源码。** 正文可以含解释示例，工作区可能残留旧文件；完整候选和成功提交点提供清晰的版本归属。

**把全部自定义 API 常驻提示词。** 许多 API 与当前任务无关；完整基础教材和按需参考在可发现性与输入成本之间取舍，宽松类型不能代替准确说明。

**由手机保存权威历史并执行生成工具。** 会依赖设备在线，不能满足服务端历史所有权和离线完成的要求。

**用服务端浏览器验证原生运行。** 浏览器不提供 SwiftUI、JavaScriptCore 桥接和系统权限；通过语法或浏览器检查不等于原生能力成功。

## 验证

[存量隔离测试](../../../../backend/src/do/web-only.test.ts)覆盖旧用途、未知用途、原生进行中 turn、网页恢复和清理、原生 ID 的 HTTP 拒绝及数据保留。历史原生生成和真机验收不再属于当前测试入口。

## 后果

原生数据可保留供明确授权的数据维护使用，但没有读取、继续生成或版本下载的产品入口。用途过滤仍是共享数据库的必要条件，不能因为原生源码目录不存在就删除它。重新引入原生能力需要独立方案，同时恢复 SDK、版本发布、取消隔离与真实设备验证，不能直接把旧会话交给网页 runner。
