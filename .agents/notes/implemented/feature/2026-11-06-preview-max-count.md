# Agent Note: 浏览器预览次数预算

Status: implemented

## 问题

生成模型可以多次预览、修改并续推，缺少次数上限会增加等待时间和模型调用。用户要求可配置上限、默认 2，0 完全关闭生成过程的浏览器检查。

## 决策

PREVIEW_MAX_COUNT 是 backend 的非负整数配置，默认 2，0 不注册 preview_widget 并使用禁用检查的 brief。每次 agent 运行独立预算：直接 HTTP 每请求，会话每次 turn 执行或恢复各自初始化。配置的取值和覆盖方式由[开发指南](../../../../docs/development.md#本地运行)拥有。

工具执行前同步占用一次预算，失败和并发调用均计数；最后一次开始时从活动工具中移除 preview_widget，下一轮模型不再看到它。工具自身仍有硬限制，阻止已排队或持有旧定义的调用启动额外浏览器。prompt 和结果说明剩余额度及耗尽后的完成规则，不把未执行检查称为通过。

0 不注册浏览器检查工具，即使 BROWSER 绑定存在也不会使用；网页捕获、输入 PNG 与手动 CLI preview 保留。直接和会话 runner 都读取同一配置，不增加客户端请求字段或改变返回 envelope。

## 曾考虑的替代方案

**只在 prompt 写次数上限。** 不能阻止模型忽略或并发超额执行，需要工具执行器硬限制。

**保留可见工具但一直返回额度错误。** 虽然不启动浏览器，仍可能导致无用续推；预算耗尽后移除活动工具，保留硬限制处理在途调用。

## 验证

`npm test` 的 157 项、`npm run test:agent` 的 20 项、`npm run test:cli` 的 35 项及类型、设计目录、文档、Notes 和 diff 检查通过。回归覆盖默认值、0、其他整数与非法值，成功和失败计数、同步并发占位、不同运行隔离，以及真实 SDK 的后续请求不再提供预览定义。直接 runner 的 0 配置即使有 BROWSER 也不注册该工具，保留 PNG 与其他工具。

隔离临时源码中的四组负例分别去掉硬限制、错误注册零预算工具、取消活动工具移除、丢弃直接 runner 的 0 配置，均被对应测试拒绝；没有在用户运行的源码中注入错误。模拟网关与临时服务器退出后清理，未重放用户请求。

当前网关的最小工具历史请求在移除活动工具后仍返回 HTTP 200，验证该兼容入口可以接收旧工具调用记录而不再声明该工具。未自动运行完整真实 Widget 生成，未部署。

静态首轮 system/tool schema 按 o200k_base 代理计数：修改前 5150，默认2为5224，0为4871。分别为 system 3736/3788/3594，工具 1414/1436/1277；不包含用户输入、图片或工具结果，不作为总请求成本测量。

## 后果

预算耗尽时可能仍有未经再次验证的修订，0 完全不验证浏览器渲染。生成 Success 的含义不扩展为质量校验全部通过；用户可以另行手动预览。

移除活动工具会改变后续工具集合与 SDK 组装的 prompt，brief 在相同配置下仍稳定。预算不作为跨进程恢复的持久化状态，会话恢复和新的 HTTP 请求建立新预算。

此需求部分扩展[直接 HTTP 生成](2026-11-05-direct-http-generation.md)和[网页预览](2026-09-30-static-ios-widget-artifacts.md)，它们继续拥有数据、布局和静态截图契约，保持活跃并同步事实；没有同一预算的记录需要归档，冻结记录保持不变。
