# Agent Note: Widget 广场数据导入导出

Status: implemented
Archived: 2026-11-05

## 问题

广场元数据保存在 D1，截图与源码保存在 R2。单独复制任一存储都不能恢复完整内容；向已有环境复制投稿时照搬同步游标，还会与目标数据冲突或被客户端已保存的增量游标跳过。需要一个可重复执行的脚本，把完整广场内容导出到固定目录，再合并到指定环境。

## 决策

`backend/scripts/gallery-data.mjs` 提供 export 和 import 子命令，支持本地与 Cloudflare 生产环境，默认本地；导入保留已有内容，新作品分配目标 update_at，重复内容跳过。Wrangler 的资源代理提供一致的本地与线上 D1/R2 接口，只连接广场 D1 与私有、公开 R2 绑定，不引入业务 HTTP 接口。

### 命令与固定目录

在 backend 下执行：

```bash
npm run gallery:export
npm run gallery:import
npm run gallery:export -- --prod
npm run gallery:import -- --prod
```

两个 npm 命令调用同一个脚本。默认读写 `backend/shared-widgets-data/`，路径相对脚本定位，不随调用目录变化；目录加入 Git 忽略。提供 `--local`、`--prod` 与本地 `--persist-to`，互斥参数和未知参数报错；`--prod` 选择 Cloudflare 生产环境，`--remote` 不作为脚本参数接受。线上操作使用配置中的 D1/R2 绑定和 Cloudflare 凭据，不依赖 App 或 Admin 口令，不增加线上 HTTP 接口。线上绑定仍为占位值时直接报错。

目录包含 v6 `manifest.json` 及按私有 R2 key 保存的全部引用产物。父记录保存 category_id，并与语言记录共同恢复生产状态，保留历史批准来源和审核时间，不导出领取租约、token 或结果凭据。deleted 只导出元数据，公开副本由已批准的完整私有产物重建；不导出用户 DO、密钥和孤儿对象。

### 导出

导出在同一 D1 快照读取所有生命周期的父记录和语言记录，拒绝活跃生产租约，下载后再次比较快照指纹。文件缺失、大小或哈希不符、生产状态变化都会失败。导入兼容 v1–v5；v1–v4 的 pending／approved 转入等待翻译。无分类的历史批准不自动恢复：双语齐全时进入 pending，未齐时先完成生产；清空历史批准标记及公开引用，保留私有产物。有效分类保留原审核语义。v4–v6 保留原始 request_hash，v1–v3 按原格式校验。分类兼容决策见[分类审核](../feature/2026-10-25-shared-widget-categories.md)。

先写同级临时目录，全部下载和校验通过后再替换固定目录；替换期间可恢复旧目录，失败时不把半成品当成备份，也不丢弃上一份完整导出。同一固定目录只允许一个导入或导出进程操作，避免读到替换中的文件。

### 合并导入

写入前校验整个目录：格式版本、字段类型与范围、唯一 ID、唯一 update_at、路径、文件存在性、字节数和哈希。v1/v2 还校验旧发布关联：未删除的 approved 必须恰好有一条发布记录，其余不能有。只接受固定文件路径，拒绝路径穿越和符号链接；不执行目录中携带的 SQL 或 Widget JavaScript。

以 shared_widgets.id 识别同一份投稿，保留源投稿的作者、名称、简介、尺寸、源码版本、时间与审核信息。目标已有相同 ID 且不可变字段一致时跳过；目标当前分类、标题、简介、译文、生产版本、状态和 update_at 保持不变，即使导出副本不同。目标删除记录不校验已清理产物，旧备份不能复活它；源删除标记不删除已有目标。相同 ID 的不可变字段或产物不一致时视为冲突，预检查阶段报错，不覆盖。相同代码但不同投稿 ID 仍是不同作品，不做内容相似性去重。

新投稿保持 shared widget ID 和固定 R2 路径，按源 update_at 顺序逐份导入；目标原子分配新的 update_at，确保已有客户端游标能获取新记录。deleted 只写投稿元数据，其他状态都复制产物。脚本报告新增、跳过与冲突数量，不复制或报告发布 ID。

先确保一份未删除投稿的全部引用产物已写入并校验，再在同一事务插入父记录、语言记录及目标 update_at。已批准记录通过 GalleryStore 发布完整语言副本，复制失败计入 publicationPending；Admin 可重试发布，重复导入仅跳过已有记录。R2 已有对象只能复用相同字节，不能覆盖不同内容；数据库主键与唯一时间索引拒绝冲突。每份投稿单独提交，失败时停止并明确报告已完成数量，重试跳过已提交投稿；不承诺整个目录跨 D1/R2 原子提交。导入创建的 R2 对象保留 requestHash，不设置 expiresAt，普通上传清理因此不会删除恢复中的资源。失败遗留的未引用对象可被同一导入复用；遇到普通上传留下的带 expiresAt 对象时拒绝复用，避免清理已经持有对象路径的竞态。

目标数据库须已应用仓库迁移，脚本只写广场业务数据，不创建云资源、不修改 schema、不清空表。导出期间暂停源环境投稿、审核、删除、翻译、补图和发布；导入运行时暂停目标的这些写入及其他导入操作；脚本不新增分布式锁或维护模式。普通公共读取可以继续，每份新投稿只有产物就绪后才可见。

### 与现有决策的关系

## 曾考虑的替代方案

**原样恢复源同步游标，只允许空库。** 能完整保留源顺序，但不能向已有广场合并。新记录需要目标分配游标，避免落在客户端已读范围内。

**直接复制 D1 SQL，不复制 R2。** 只能恢复目录记录，图片和源码会缺失，因此导出包必须同时包含被引用的产物。

**覆盖目标同 ID 记录或先清空数据。** 会改写已有审核结果或丢失目标内容，也不能通知已缓存的客户端撤回旧数据，与用户确认的合并规则冲突。

**仅用代码哈希去重。** 相同代码可以对应不同尺寸、截图或投稿身份。使用既有 shared widget ID 识别重复，不引入新的内容合并语义。

## 验证

[脚本测试](../../../../backend/scripts/gallery-data.node.test.mjs)的 14 项 Node 测试通过，使用独立临时目录与真实本地 D1/R2 验证往返、目标状态保留、时间游标推进、重复跳过、损坏输入和冲突拒绝，以及 v1–v4 兼容、v5 双语往返、历史批准、活跃租约拒绝、导出变化和公开复制失败恢复。R2 故障和真实 SQLite 触发器验证逐投稿失败及重试；子进程验证固定目录锁；CLI 入口验证固定目录与本地自定义状态路径；有数据的旧 schema 迁移保留投稿与资源身份。

[广场 Workers 测试](../../../../backend/src/gallery/gallery.test.ts)验证无上传期限的导入对象在 D1 提交前不会被普通上传清理。Node 测试接入 backend check，随根 npm run check 执行。生产参数与连接错误由替身验证，尚未执行真实 Cloudflare 生产资源往返。

## 后果

导出包包含用户提交的截图、源码和作者标识，应作为数据备份保管，不加入版本控制。源 SDK 版本原样保留；脚本不把历史代码升级为当前 SDK，也不保证当前客户端能采用旧版本代码。

逐投稿事务支持断点重试，但失败可留下部分已导入内容和未引用的 R2 对象。无期限的导入对象不会自动回收，放弃恢复时需要人工核对引用后清理；这避免普通上传的清理流程破坏长时间恢复。锁属于本机固定目录，不代替目标环境的写入协调；不同目录或不同机器的导入仍由维护者确保互斥。

同步游标属于目标环境，导出包不用于把在线目录回滚到过去，也不恢复客户端缓存，也不把源删除覆盖到已有目标。自动覆盖、物理数据库克隆、定时备份和压缩加密不在本次范围；固定目录和版本化 manifest 保留后续扩展空间。

删除标记的终态与清理语义由[Admin 删除](../feature/2026-10-22-admin-gallery-deletion.md)拥有；两篇保持活跃。
