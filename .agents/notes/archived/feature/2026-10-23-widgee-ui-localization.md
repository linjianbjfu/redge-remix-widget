# Agent Note: Widgee 客户端与接口文案中英文本地化

Status: implemented
Archived: 2026-11-05

## 问题

Widgee 的产品界面、系统权限用途说明和服务端错误需要使用用户选择的语言，而聊天正文、用户数据和生成的 Widget 具有独立的内容所有权。只替换界面中的中文无法覆盖缓存错误、默认标题和共享 SSE 广播；把语言保存进会话又会改变多设备共享与重试语义。

## 决策

支持 English 和简体中文，跟随 iOS 系统／系统中的 App 语言设置，英文为回退。App 不另设语言偏好，也不承诺进程内即时切换。日期和数字继续使用用户区域偏好，不由界面语言强制覆盖。

### 界面与内容所有权

主 App、WidgetKit 和 RuntimeCore 按各自资源 bundle 使用 String Catalog；系统权限用途说明分别由 App 与扩展的 InfoPlist catalog 提供。语言解析、资源归属与宿主接口见 [iOS 设计](../../../../ios/DESIGN.md#宿主界面语言)。

本地化覆盖产品导航、按钮、占位符、状态、错误、无障碍标签、WidgetKit 配置以及宿主拥有的缺省控件。脚本传入的标题、表单、按钮和图表数据、任意脚本异常与第三方错误详情保留原文；用户可见错误类别由独立适配器翻译。`RuntimeError.errorDescription`、`modelFacingDescription` 和 `Capability.displayName` 保留技术诊断含义，模型不接收用户提示映射。缺省 alert 按钮可以显示“好”，回传给脚本的值仍是 `OK`。

LLM 回复、AI 标题、首条问题截取标题、作者本地 Widget 和用户输入保持原内容。共享投稿的派生产物由双语生产流程翻译，审核文案按语言编辑。语言参数不进入 prompt、工具定义、模型输入摘要或生成内容约束，聊天界面本地化不调用模型翻译；广场使用独立生产 CLI。示例脚本、模型教材、开发后台、CLI 和旧网页捕获业务保持独立范围。

### 请求投影与持久化

Widgee 的会话和广场 API 统一使用 URL 查询参数 `language=en|zh-Hans`，覆盖业务 JSON、multipart 和 SSE；广场公开资产使用目录返回的语言版本 URL。省略或未知值回退英文，重复参数取首值；参数位置和错误契约由 [Widgee 协议](../../../../docs/widgee-protocol.md)拥有。查询参数能覆盖 GET 与流式订阅，也能避免 JSON 与 multipart 维护不同解析规则。

语言属于请求或订阅者，服务端在响应出口映射稳定错误代码和 `titleSource=pending` 的标题。实时 Hub 为每个订阅者分别映射共享帧；历史 JSON、有限回放和目录摘要采用相同规则。映射不改写事件、会话或产物，不改变 seq、cursor、summaryVersion、目录 version、输入摘要及 turnId 幂等恢复。同一会话的中英文订阅者因此可以同时收到各自的系统提示。

客户端按错误代码重新显示缓存与旧响应中的已知系统错误，按 `titleSource` 显示默认标题，不把上次请求的翻译固定为永久内容。显式命名为“新对话”的 custom 标题不被替换；旧缓存缺少来源时不靠字符串猜测改写。缓存中的持久错误与实时接收的持久错误都进入历史；无持久 seq 的临时错误使用恢复提示。

语言不属于账户、会话、草稿和投稿重试身份。广场浏览缓存记录语言，切换时清空目录、游标及图片；聊天缓存身份不变。聊天草稿及清理任务继续使用不含 language 的既有 URL 身份；切换语言无需清空历史或迁移已采用 Widget。

服务端文案按语言保存在 `backend/src/widgee/locales/en.json` 与 `zh-Hans.json`，映射逻辑只引用资源键。翻译资源归属与新增语言步骤由[开发指南](../../../../docs/development.md#翻译资源)维护。

## 曾考虑的替代方案

**App 内另设语言切换。** 可以即时选择，但增加偏好持久化、跨 bundle 与系统控件一致性工作；采用用户选择的 iOS App 语言设置。

**仅由客户端翻译错误代码。** 对 iOS 较简洁，但不能满足接口按 language 返回文案的要求。服务端提供请求级映射，客户端另保留代码映射以覆盖离线缓存和旧响应。

**把 language 放进 POST JSON，或只用 Accept-Language。** 请求体不能统一覆盖 GET 与 SSE，multipart 还需另一份解析；Header 不符合显式 language 参数的选择。URL 参数统一承载当前调用方式。

**把语言保存到会话并持久化翻译后的事件。** 单语言广播更简单，但无法满足多设备不同语言、切换后的历史展示和幂等恢复，因此只投影系统字段。

## 验证

资源完整性通过 `npm run verify-localizations` 接入顶层 `npm run check`：要求五份 catalog、英文源语言、完整的中英文翻译、对应的插值参数以及全部权限用途说明。backend JSON 要求语言文件齐全、键集合一致且文案非空。九项可执行测试用缺失／空白／未完成翻译、参数不匹配、缺失 catalog 和权限条目，以及 backend 文件缺失、键不匹配和无效值等反例证明门禁会拒绝非法输入。

backend 的 119 项相关测试覆盖鉴权、语言回退和重复值、JSON 与 SSE、独立订阅者、持久化与版本稳定、同 turn 重试以及广场分页；绕过订阅者映射的负例被真实 Worker 测试拒绝。客户端测试覆盖请求查询与正文、草稿身份、离线错误与标题、实时／缓存历史一致性和原始诊断。中英文大字号导航测试、签名 App／Widget 构建、包资源与权限 catalog 测试通过；Runtime 的 94 项测试及 SDK 一致性门禁通过。

原生宿主演示使用独立 Worker 的真实模型产物，经普通源码编辑器保存运行；确认框、日期选择器和扫描不可用界面使用中文，模型生成标签及源码保持原文。主 App 的真实模型演示完成英文生成、保存与简体中文重启，采用后源码 SHA-256 与服务端产物一致；两个 GUI PR 均保留准确提交、运行环境与 GIF 证据。

## 后果

服务端映射和客户端离线映射需要随稳定错误代码一起维护。未传 language 的旧调用者会看到英文系统 message 与未命名标题，机器代码和状态保持不变。首版不提供繁体中文资源；系统按已声明资源匹配。

界面语言与用户／LLM 内容可以不同，这是内容所有权的直接结果。任意技术错误详情不承诺全文翻译，用户可见主提示仍提供中英文。

String Catalog 的行为必须通过 Xcode 编译后的 bundle 验证，普通 SwiftPM 命令行测试不会编译 catalog。新增 package 资源后的旧增量构建可能保留不含语言文件的内嵌 bundle；清理独立构建产物并重建后，安装包资源与语言测试通过。系统真实授权弹窗、主屏幕 WidgetKit 选择／配置流程尚未进行视觉验证；资源编译和 bundle 测试不替代这些设备检查。
