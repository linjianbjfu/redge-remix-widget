# Agent Note: Widgee 聊天草稿图片裁剪

Status: implemented
Archived: 2026-11-05

## 问题

用户添加参考图片后，需要去掉无关区域，再将所见内容交给模型。裁剪改变图片字节、尺寸及摘要，必须与发送重试使用不可变图片的规则兼容。

## 决策

草稿图片的预览提供自由矩形裁剪，取消保留原图，完成后保存当前处理版本的选区。选区以图片左上角为原点，按图片尺寸归一化；布局变化不改变选中的像素。像素换算拒绝图片范围外、非有限值及零面积选区。具体交互和处理限额由 [iOS 使用说明](../../../../ios/README.md)与 [iOS 设计](../../../../ios/DESIGN.md)拥有。

每次裁剪创建新文件 ID 和内容摘要，保持附件位置与总张数。后台准备像素后，在主 actor 检查原身份、导航代次、会话及原附件仍有效，再写文件并替换草稿引用；写入与引用替换之间没有异步让出。保存期间禁止发送和重复保存；取消、处理或写入失败不改变原引用。

原文件只有在草稿与 pending 都不再引用时才删除，重试与已接受消息的字节不得原地修改。加载草稿时清理未引用的 UUID 文件，同时保留 pending，以回收写完新文件却尚未保存引用就退出的遗留。删除附件也遵循引用保护规则。历史图片只可预览，图库原件不变。

本能力扩展[图片输入](2026-10-22-widgee-chat-image-input.md)的草稿编辑；该笔记继续拥有导入、上传、恢复与缓存决策，保持活跃。网页区域 capture 的 DOM/XPath 选择不涉及相册像素编辑，没有完全取代的记录。

## 曾考虑的替代方案

**只在相册选择时裁剪。** 用户无法在添加后再次调整，而且替换当前支持有序多选的 PhotosPicker 会改变选择流程。保留多选，编辑入口放在草稿预览。

**保留相册原图及裁剪参数，发送时重新生成。** 可以恢复被裁掉的区域，但需要长期保存更大的原图并维护编辑版本，发送前预览与恢复也需要重新渲染。本方案复用现有已处理图片，保证发送使用预览对应的持久化字节。

**覆盖原附件文件。** 草稿可能与 pending 共享文件，覆盖会使重试内容与既有摘要不一致。新文件加引用替换允许失败回退并保留发送中的旧版本。

## 验证

[验证数据](../../../../docs/measurements/widgee-chat-image-crop-2026-10-22.json)记录宿主 34 项测试、真机 11 项图片测试及完整 UI 流程。像素测试用不同颜色的左上、中心和右下区域检查坐标与透明度，并拒绝非法矩形；同步信号控制删除附件、删除会话、切换页面、身份失效、发送和取消发生在处理完成前。写入目标被普通文件占用时，原引用与文件仍可恢复；重启清理只回收孤儿，pending 字节保持一致。

iPhone Air / iOS 27.0.1 验证五张选择、移除补选、裁剪取消、保存、重新打开裁剪、冷启动、发送后重启和历史预览。第一张参考图上半部分的 99999 被裁掉；上传结果为 1800×594px，真实模型只返回保留的五个编号 11111、22222、33333、44444、55555。[裁剪截图](../../../../docs/measurements/widgee-chat-image-crop-2026-10-22.png)与[输入栏截图](../../../../docs/measurements/widgee-chat-image-composer-2026-10-22.png)来自这条真实流程。

## 后果

裁剪以已缩放的图片为基础，不能恢复导入时丢失的细节；连续裁剪会丢弃选区外内容并可能重复 JPEG 编码。当前没有撤销历史、恢复相册原图、旋转或预设宽高比；需要恢复被裁区域时可移除后重新选择图库原件。新文件 ID 与独立裁剪入口允许以后增加非破坏性编辑，不改变上传协议。

新旧文件在替换时短暂共存；清理失败不撤销已经保存的裁剪，错误明确指出旧文件清理失败。图片文件与 UserDefaults 引用分别保存，加载时的引用清理负责回收中断产生的孤儿。

应用保持竖屏，横竖可用区域的适配计算由单元测试覆盖。裁剪选区提供 VoiceOver 移动动作，四角支持可调整动作，但本轮没有人工验证 VoiceOver 操作。
