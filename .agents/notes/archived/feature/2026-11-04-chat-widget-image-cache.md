# Agent Note: Chat Widget 预览使用持久化图片缓存

Status: implemented
Archived: 2026-11-05

## 问题

Chat 的 Widget 预览只在内存缓存 ViewNode，切换会话或进入后台后会清空。重新查看需要再次执行 JS、网络请求和原生视图布局。用户要求缓存图片，保留图片点击与配置入口，配置更新后更新缓存图，删除会话时清理所有相关图片，并进行实际 E2E 验证。

## 决策

[ChatPreviewStore](../../../../ios/Widgee/Chat/ChatPreviewStore.swift)为可见卡片提供本机图片缓存。[ChatWidgetPreview](../../../../ios/Widgee/Chat/ChatWidgetPreview.swift)显示 Image；内存或磁盘命中时不下载源码、不执行 JS 或脚本网络请求，也不重新布局整棵 WidgetNodeView。

无匹配图片时，继续校验完整源码并通过 ChatLivePreview 的真实 Widget 注册表和独立草稿副本执行，再用共享内容容器与 ImageRenderer 生成 PNG。资料库默认的 stub fallback 不进入 Chat；只复用图像生成和有界文件缓存能力，两个缓存目录、来源和身份保持独立。后端、SDK、配置表单及显式采用语义不变。字段、限额和生命周期由 [iOS 设计](../../../../ios/DESIGN.md#后端通信边界)拥有，执行命令由 [iOS README](../../../../ios/README.md)拥有。

### 配置、留存与删除

配置页关闭后先完成图片持久化，再按最终草稿指纹选择图片；配置改变时生成一次新图，没有改变时可复用。配置宿主的 projectWidget 保留运行实例 state，不能直接把可能未保存的树作为持久图片来源。图片持久化没有转换内容时保留原文件字节，避免仅因 JSON 重编码改变草稿指纹；不更改既有采用指纹算法。

缓存键覆盖服务/用户/会话对应的草稿身份、源码 revision/hash/SDK、最终草稿内容、尺寸和显示环境。PNG、生成时间及可访问性文本原子保存；离开页面和后台保留磁盘记录。内存缓存最多 12 项且解码像素预算 20 MiB，磁盘预算 50 MiB。离屏卡片释放 UIImage，保留时间等轻量元数据，避免图片释放时标题说明高度反复变化。

图片说明展示快照时间，保留手动刷新，不按 refreshAfter 自动运行。时间表示图片生成时刻，不保证脚本内每项数据的观测时间。同版本同尺寸更新期间保留旧图；执行失败显示错误，不将旧图冒充新配置成功结果。有效图片即使无法写入缓存也能显示，损坏缓存重新生成。

[ChatDraftStore](../../../../ios/Widgee/Chat/ChatDraftStore.swift)统一处理主动删除和同步删除。删除使任务失效并取消，清理该身份所有版本、配置和显示变体的内存图片与磁盘记录，也删除 `Widgets/<draft-id>/` 中配置页生成的快照和图片。PNG 写入和删除在同一 actor 排序，已删除身份拒绝迟到写入；配置宿主沿用停止与代际检查。清理失败向调用方报告，原有 SQLite 清理任务保持待处理，其他会话及已采用 Widget 的独立数据不变。

### 决策归属

本记录部分取代[聊天联网预览](2026-10-20-widgee-chat-network-preview.md)的内存树留存和后台失效规则，以及[内嵌 Widget 预览](2026-10-19-widgee-chat-title-preview.md)中直接展示原生树的呈现方式。两篇仍拥有取数、版本、取消、标题和采用理由，保留并互链。

[聊天配置草稿与真实预览](../../proposed/feature/2026-10-20-widgee-chat-saved-configuration-preview.md)继续拥有草稿隔离、真实 API、采用复制和未完成的完整采用 UI 验收；本任务不合并或关闭其余验收。[资料库缩略图](2026-10-19-widgee-tabbed-chat-library-ux.md)和[桌面布局一致性](../bug-fix/2026-10-19-widgee-widget-preview-parity.md)继续拥有各自图片来源及共享布局。[取消与超时](../../proposed/bug-fix/2026-10-22-widgee-preview-cancellation-timeout.md)的独立调查不由图片缓存替代。

取代检查覆盖上述缓存、配置及资源清理机制，没有完全取代的记录，无归档或删除。

## 曾考虑的替代方案

**继续只缓存 ViewNode，并取消生命周期清空。** 能减少 JS 重跑，但列表仍需构建原生控件，跨进程也没有可直接显示的图片。

**只缓存内存图片。** 后台释放或重启后仍需重算；有界磁盘缓存支持回访和重启。

**直接采用资料库完整取数流程。** 其来源是已采用身份和匹配快照，默认 fallback 为 stub；Chat 保留真实取数与独立草稿，只复用图像和文件能力。

**直接复用配置页当前成功树。** 可以减少一次 JS 和网络请求，但运行 state 不保证保存，现有快照也没有最终草稿指纹。按保存数据重建，避免缓存无法重建的临时画面；可验证的跨入口快照出处出现后可重新考虑。

**命中缓存后每次进入仍后台刷新。** 继续重复运行脚本和网络，并可能在用户查看时跳变。选择明确的配置/版本失效和用户刷新。

## 后果

重复查看不再运行脚本或布局整棵原生树，代价是磁盘空间、解码图片内存和首次截图编码成本。缓存图可能包含旧数据，用户通过时间和刷新判断；不承诺首次无缓存也更快。

图片只有扁平的内容摘要和配置动作，不保留原生树逐控件的全部无障碍导航。缓存保存在应用本机、排除备份，不自动上传；脚本自身联网的能力不由此限制。解码缓存预算不等于整个应用的 RSS 或系统图像缓存预算，未测全进程峰值。

辅助字号下说明与配置/刷新操作分行排列，避免时间说明被按钮压到过窄的列。原有采用按钮的深色对比度问题由 Beads `webclip_widget-ba7` 独立跟进，不据此宣称整个应用的大字号视觉验收完成。

缓存不证明权限、真实远端服务、主屏幕调度或首次运行超时已解决；已有运行时限制继续存在。客户端产物 API 不变。当前版本已原位安装到 iPhone Air / iOS 27.2 并正常启动；真机没有运行会重装宿主的 XCTest，图片缓存 E2E 证据来自模拟器。

## 验证

在复用的 iPhone 17 / iOS 27.2 模拟器上执行真实应用与原生图片生成。E2E 使用隔离 Worker 的正式 ChatStore/HTTP handlers 与固定合成脚本，不调用模型、不复制用户聊天内容，不改用户真机配置。

- `ChatPreviewCacheTests`、`ChatPreviewTests`、`ChatDraftTests`、`ChatNetworkPreviewTests`、`SDKArtifactTests`、`LibraryUXTests` 共 40 项通过。覆盖内存/磁盘复用、键隔离、预算、内联图片在运行时退出后和重载后的像素一致性、损坏重建、失败保留旧图、不可写缓存、所有变体删除、迟到写入和配置快照清理；已采用快照图片保持可读。
- 辅助字号的实际预览控件组合另有原生布局回归通过，合计 41 项；中文深色大字号 E2E 在将图片完整滚入可见区域后复验，不以离屏 AX 元素存在代替图片可见。
- `node ios/scripts/test-chat-preview.mjs <xctestrun> <UDID> <evidence>` 的五个 E2E 场景整套通过，无跳过：点击图片和配置、精确保存新值、多个源码版本/三种尺寸/配置变体的缓存、前后台和冷启动零 JS、主动删除、远端删除与迟到网络响应、失败刷新保留旧图、中文深色大字号及性能样本。配置快照清理加入后，相关完整配置/重启/删除 E2E 另通过，确认 PNG、内存及配置快照文件均为零。
- 原树预览 App 在同一零 JS E2E 回访断言中按预期失败；移除图片持久化的无变化保护时，草稿字节和指纹回归按预期失败，恢复后通过。早期夹具会话定位、按钮未完整进入可操作区域及 PNG 编码字节比较失败不计为成功结果；最终以明确会话参数、有效视口、真实像素及完成状态验收。
- 聊天缓存宿主 35 项、`verify-ios`、`verify-localizations`、隔离 Worker smoke、文档/Notes 和 diff 检查通过。新增和重写的缓存、预览及 E2E Swift 文件通过 SwiftLint strict；既有文件非修改行的 26 条诊断保留，本次修改行无新诊断。

主要证据位于本地 `.playwright-mcp/chat-image-cache-6mk/`：`e2e-verified/tests.xcresult`、`ui-owned-snapshots/tests.xcresult`、`unit-owned-snapshots.xcresult`、`baseline-verified/`、`performance.json` 及截图。可重跑命令见 iOS README，模拟器流程见[开发说明](../../../../docs/ios-simulator-testing.md)。

## 性能证据

时钟从打开已有会话开始，到应用发布预览后的两个 CADisplayLink 帧；不包含进程启动、模型或公共网络延迟，包含固定本地 HTTP 边界。XCTest 的点击和等待壁钟另外记录，不充当绘制时间。基线 App 使用改动前源码和相同 DEBUG 测量钩子，回访须仍执行 JS；候选与基线使用同一设备和测试代码。

| 固定负载与操作 | 基线中位数 | 图片版本中位数 | 样本 |
| --- | ---: | ---: | ---: |
| 单结果，回访会话 | 92.6 ms | 76.4 ms | 各 5 |
| 20 个历史结果，回访会话 | 126.5 ms | 111.4 ms | 各 5 |
| 单结果，重启后打开 | 143.5 ms | 126.5 ms | 各 5，含首次 miss |
| 20 个历史结果，重启后打开 | 194.9 ms | 179.1 ms | 各 5，含首次 miss |

回访及已经生成图片的重启样本中，JS 从每次一次降为零；冷启动组的首个无缓存样本仍运行一次。首次 miss 的单次样本为 178.1 → 211.6 ms 和 211.4 → 225.8 ms，截图成本没有被隐藏。以上是小规模固定负载证据，不是通用性能保证，不涵盖流式输入、任意长会话或真实远端 API 可用性。原始样本和最大值保留在证据目录。
