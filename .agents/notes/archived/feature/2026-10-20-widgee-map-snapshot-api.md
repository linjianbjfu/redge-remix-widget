# Agent Note: Widgee 地图位图 API

Status: implemented
Archived: 2026-11-05

## 问题

Widget 脚本需要按显示尺寸生成地图图片，并显示路线与路况。地点搜索和路线摘要无法提供可交给 Image 的地图位图，Widget 静态视图树也不能直接嵌入交互式地图。

## 决策

`maps.snapshot` 使用 MKMapSnapshotter，standard 和 hybrid 的交通层通过 preferredConfiguration.showsTraffic 开启。路线来自 MKDirections 的实际几何数据，以快照的坐标投影绘制；不使用端点直线代替导航路线，也不以预计用时替代交通层。参数、单位和限制由 [SupportedAPI.swift](../../../../ios/Packages/WidgeeRuntime/Sources/WidgeeRuntimeCore/SupportedAPI.swift)拥有，实现与缓存职责见 [iOS 设计](../../../../ios/DESIGN.md#地图位图)。

输入在原生调用和离线 stub 之间共用验证器。尺寸上限与现有 Widget 图片上限一致，路线地图至少 64pt，确保自动视野适配能为端点和归属标识保留空间。明确指定 region 时尊重调用方视野；只有路线时才自动适配。路线与地图共用 7 秒预算，取消传递给两个原生请求，不建立额外后台生成任务。

图片通过内联 PNG 返回并随现有 Widget 快照持久化，避免每次刷新在共享 ImageStore 积累无界图片 ID，也使聊天预览不必读取共享图片文件。绘制保留完整底图，路线和标记避开底部 32pt；脚本必须保留地图归属标识。地图作为背景时使用完整 context 尺寸，根节点抵消宿主 14pt 留白；叠加文字单独留白。宿主不全局移除所有 Widget 的内容边距。

聊天只通过 PreviewMaps 开放 snapshot，每次最多 4 张；其他地图方法保持示例模块，尤其不能打开系统地图。截图不隐式读取当前位置，用户位置仍需脚本显式获取。聊天的私人定位与已采用配置继续隔离；离线校验使用带“示例地图 · Offline”标记的确定性位图。

保存用户位置供桌面读取的要求由[桌面 Widget 按当前位置刷新](2026-10-21-widgee-widget-current-location.md)部分取代：当前位置在每次实际刷新时显式获取，固定地点配置仍可持久化。

模型通过生成的 SDK 索引发现方法，通过 module:maps 按需读取完整参数及背景、路线、错误处理示例。详细参考不进入首轮主提示词。移植门禁将方法列为明确的 Widgee 扩展，不改写 Minis 来源清单；缺失扩展和额外未知 API 都被拒绝。

生成会话的 SDK 哈希沿用严格匹配规则：旧 SDK 会话历史可读，新能力使用新会话，已采用脚本继续运行；不引入旧会话迁移协议。此能力扩展[原生运行时](2026-10-19-widgee-ios-native-runtime.md)与[聊天联网预览](2026-10-20-widgee-chat-network-preview.md)，两篇记录仍约束运行时归属、私人数据和缓存，保留活跃。

旧产物因 SDK 哈希变化被拒绝预览的问题及读取兼容规则，见[兼容旧 SDK 的产物预览](../bug-fix/2026-10-20-widgee-compatible-artifact-preview.md)。

## 曾考虑的替代方案

**直接截取交互式 MKMapView。** 依赖视图生命周期和加载完成时机，不适合作为 Widget 扩展的绘制入口，采用专用快照 API。

**外部静态地图服务。** 引入供应商账号、费用、覆盖范围和坐标语义。MapKit 真机已经能生成路况与实际路线；若未来覆盖范围或可靠性不满足需求，再单独评审供应商，不因一次服务失败自动切换。

**只返回路线摘要或普通地图。** 实现更简单，但不能满足位图中的导航路径和真实路况，因此不作为成功结果。

## 后果

地图调用不需要 WeatherKit 服务权限。本次 iPhone Air 验证未调整开发者账号权限即可生成底图、交通色带和真实路线。早期探测及一次后续交通请求返回 `MKErrorDomain Code=2`、`com.apple.maps.snapshot.failedtiles Code=-5`；这些失败不计作通过，也不能据此认定账号权限不足。服务仍可能失败，错误保留原生诊断；没有静默去掉交通层、假造路径或自动切换供应商。

生成时间不是交通观测时间，不承诺实时导航、后台持续定位或持续刷新。失败时，只有宿主未收到成功视图才可沿用匹配的旧快照；脚本自行返回的错误界面仍是一个成功视图。此次不提供交互式地图、语音逐向导航、公交或骑行路线，也不增加服务端地图代理。

## 验证

参数与 stub 的 4 项 Swift 测试覆盖非法输入和三种尺寸；真机测试覆盖原生配置、取消与超时、路线视野、聊天隔离与请求上限、内联图片持久化。背景测试比较三种尺寸在聊天、缩略图和桌面宿主的边缘像素，并要求带留白的反例失败。真实地图不使用随交通变化的像素黄金图作为 CI 断言。

真机联网验收成功获取普通地图、路况及路线位图，截图可辨认交通色带。UI 验收覆盖示例的三种尺寸、配置、缩略图、冷启动与实际桌面；真实模型两轮生成与修改、三种尺寸预览及采用由 MapSnapshotE2ETests 覆盖。运行方式和会修改的测试数据见 [iOS README](../../../../ios/README.md#真机详情页测试)。

首轮 system 文本使用 o200k_base 测量从 9695 增至 9719 tokens，增加 24；工具定义未增加，地图详情按需读取。该数字是本地 tokenizer 计数，不是服务商计费统计。后端 29 项聊天测试、类型检查、SDK 一致性、移植门禁及其负例、SwiftLint、文档和 Notes 门禁覆盖此改动。
