# Agent Note: Admin 删除广场投稿

Status: implemented
Archived: 2026-11-05

## 问题

Admin 能查看与审核投稿，但不能移除指定作品。删除涉及发布目录、不可变截图和源码，以及客户端增量缓存；仅删目录会遗留产物，仅删 R2 会暴露失效条目，完全忘记投稿 ID 还会允许迟到的上传重试重新创建它。

## 决策

Admin 的待审核、已通过、已拒绝投稿详情均提供“删除 Widget”。操作前显示包含名称的确认框，说明将从广场移除且不能撤销，已经添加到“我的 Widget”的独立副本不受影响。请求过程中禁用该投稿的审核和删除操作；成功后清空详情并刷新当前筛选列表，失败时保留可重试入口。

### 服务端删除与失败恢复

shared_widgets 的 status=deleted 是不可恢复终态。删除保留投稿元数据，阻止同一提交键复活；这不是清除全部数据库信息的物理删除。状态与同步版本的分配由[单表状态同步](../architecture/2026-10-22-gallery-single-table-sync.md)拥有，不使用独立删除字段、发布表或缓存核对接口。

`DELETE /v1/admin/shared-widgets/:sharedWidgetId` 仅接受 ADMIN_TOKEN。数据库先将状态改为 deleted 并更新 update_at；已删除记录可重复调用且不推进版本。从未存在的 ID 返回 404，不触碰可能正在上传的同路径对象。提交与审核拒绝 deleted，最终写入不能清除终态。

删除标记提交后的业务详情和管理产物读取返回不存在，Admin 普通列表隐藏该投稿；公开状态增量返回最小删除标记。公开资产 URL 的撤回还依赖清理与缓存到期，见[公开资源协议](../../../../docs/widgee-protocol.md#公开资产与撤回)。已开始传输的响应和客户端已经获得的字节不能撤回。

D1 提交后清理该投稿在私有和公开桶中的全部语言/版本产物，完成返回 204。R2 清理失败返回 202，表示文件等待清理；Admin 展示该状态。定时清理对 deleted 投稿删除遗留产物，不受普通上传期限限制，覆盖迟到上传或复制留下的对象。重复删除可再次清理。D1 失败时不删除产物，也不报告成功。

### 缓存与备份

客户端通过状态增量移除卡片和对应图片，目录与 updateAt 游标原子保存，已采用的独立资料库副本保留。网络或保存失败不能把未知状态当成删除；分页与旧缓存升级由单表同步记录拥有。

备份保留 deleted 状态及元数据，不要求或复制已删除产物。合并保留目标状态：旧备份不能复活已删除目标，源删除也不覆盖现有有效目标。目标不存在的删除记录只导入元数据。具体格式、固定目录和失败恢复由[导入导出](../process/2026-10-22-gallery-data-transfer.md)拥有。

### 与现有记录的关系

[分享与审核](2026-10-22-widget-gallery-sharing-moderation.md)继续拥有不可变投稿与本地采用。本记录拥有管理删除交互、终态与跨存储清理；单表同步替代独立 deleted_at 与存在性核对，三篇均有独立价值并保持活跃。

相关决策：[Shared Widget 中英文内容与缩略图](../../implemented/feature/2026-10-23-shared-widget-localization.md)拥有语言产物与公开发布扩展；删除保留本记录的终态与同步原则，清理覆盖两个桶。

## 曾考虑的替代方案

**直接物理删除 D1 两表，再删除 R2。** 无法阻止相同提交键的迟到重试重新创建记录；R2 删除失败时也失去持久的清理依据。保留 deleted 状态可同时表达终态和清理意图。

**只从发布表删除。** 投稿仍可能出现在 Admin，审核重试还可能重新插入发布记录，也没有删除截图与代码。删除需要覆盖完整生命周期。

**增加 gallery_changes 同步删除事件。** 可以保留完整变化历史，但客户端只需最终状态。单表 update_at 已能同步移除，不增加事件表。

**本次只做服务端删除。** 实施范围较小，但不能清除客户端已缓存卡片。采用客户端核对使已缓存用户也能在下次成功刷新时移除卡片。

## 验证

[广场 Workers 测试](../../../../backend/src/gallery/gallery.test.ts)覆盖三种审核状态删除、鉴权、幂等、未知 ID、公开与管理产物不可读。真实 SQLite 触发器验证 D1 失败保留数据，R2 故障验证 202 与定时清理；并发审核和受屏障控制的迟到上传验证同一 ID 不会复活。

[iOS 测试](../../../../ios/WidgeeTests/GalleryTests.swift)验证状态增量移除卡片与图片、本地副本保留和失败重试；[导入导出测试](../../../../backend/scripts/gallery-data.node.test.mjs)验证删除状态不复活目标，也不覆盖现有目标。当前验证数量与迁移证据由[单表同步](../architecture/2026-10-22-gallery-single-table-sync.md)维护。

Admin 浏览器验证使用隔离本地 Worker 及既有真实模型 QA 投稿的存储副本。取消确认不发出 DELETE；确认后返回 204、列表移除目标并显示成功。单表版本还验证下一次时间增量返回 deleted 标记及资源 404。截图与真机 xcresult 保存在忽略的 .playwright-mcp/gallery-delete/；未删除默认开发环境中的投稿，未执行生产迁移或部署。待审与拒绝删除由后端测试覆盖，浏览器实测已通过投稿。

## 后果

deleted 状态及投稿元数据长期保留，图片和代码从 R2 删除；该能力不是个人数据完整擦除接口。已经采用、离线缓存或正在下载的内容不能强制回收。

状态同步不是实时推送；客户端成功获取并保存变更后移除卡片。未升级客户端不能使用新协议，需协调发布。

R2 清理最终完成依赖定时任务或重试；删除事务先撤销目录可见性与管理读取，公开 URL 的撤回受缓存窗口约束。备份格式与迁移需协调发布，导入期间也需暂停删除，遵守既有写入互斥要求。
