# Agent Note: Widgee 聊天每条消息最多五张图片

Status: implemented
Archived: 2026-11-05

## 问题

用户需要在描述 Widget 时附加图片，表达布局、样式或图片中的信息。原生聊天需要同时保留文字、附件顺序和实际图片，保证发送重试、Worker 恢复与历史重开使用同一份内容。网页 capture 的 XPath 与工作区语义不适用于相册输入。

## 决策

原生聊天以文字加最多五张有序图片作为一次不可分割的输入。纯文字继续使用 JSON，图片通过有界 multipart 与 turn 一次性接受。具体限额、错误码、图片读取与幂等契约由 [Widgee 协议](../../../../docs/widgee-protocol.md#图片附件)拥有。

### 不可变输入与恢复

服务端先限制实际流量，再验证所有图片的格式、完整解码、尺寸与字节数。PNG 的压缩像素和 ICC 数据在解码前限制膨胀量；JPEG 的解码预算覆盖允许的 2048px 图片。turn、分块图片快照和公开用户消息在同一事务提交。重试身份包含文字和有序摘要；输入不同不能复用同一个 turnId。读取上传正文会让出执行权，因此正式接受前重新检查会话仍存在。

模型首次执行和恢复执行都从不可变快照取得实际图片块；后续轮次沿用持久化 pi image_ref。含图片的会话关闭自动文字压缩，因为文字摘要不能保持原图中的可追问信息；模型上下文超限时明确失败。公开事件只保存元数据，正文通过会话内鉴权接口读取，避免图片放大历史分页和 SSE 单行。

### 客户端所有权

相册原图交付后暂存到独立受保护目录，后台处理方向、缩放、透明度和元数据。处理中重启可从暂存原图或已落盘的处理结果继续；相册尚未交付数据时保留明确的重选错误。导入任务绑定原服务、用户及会话，导航不改变归属。

草稿和 pending 文件独立于可淘汰历史缓存。新会话创建或代际恢复先复制文件并保存目标引用，清除源引用后才删除源文件。重试始终使用已处理字节，不重新压缩。公开用户消息证明接受后，图片可进入 SQLite 缓存；仍被草稿引用的文件继续保留。删除会话后，迟到导入及下载均不能恢复已删除内容。具体缓存预算与生命周期由 [iOS 设计](../../../../ios/DESIGN.md)拥有。

历史列表使用小尺寸缩略图，预览显示实际上传版本。下载失败不阻断文字或历史游标，用户可重试。图片用于模型参考，不自动成为 Widget 长期显示素材；相机、纯图片发送和独立素材采用需另行设计。

### 决策归属

本能力部分扩展[原生聊天](../../implemented/feature/2026-10-19-widgee-widget-chat.md)及 [SQLite 会话缓存](../../implemented/feature/2026-10-21-widgee-sqlite-session-cache.md)；两篇继续拥有历史权威、幂等与缓存生命周期，保持活跃。[网页多模态捕获](../../implemented/feature/2026-10-05-region-capture-multimodal-widget.md)继续拥有网页输入约束。没有完全取代的活跃记录。[草稿图片裁剪](2026-10-22-widgee-chat-image-crop.md)拥有预览中的编辑入口、草稿文件替换和 pending 引用保护。

## 曾考虑的替代方案

**直接在 JSON 和 SSE 中内嵌 base64。** 会放大请求、持久化事件和历史分页，并受 iOS SSE 单行上限约束。二进制上传与独立读取让历史恢复不必下载图片正文。

**先逐张上传，再提交图片 ID。** 可独立重试，但需要未提交附件、孤儿回收和额外状态。五张以内的有界请求与 turn 一次接受；大文件需求出现时再考虑分离上传。

**复用网页 capture 接口。** 底层 blob 可以复用，相册图片不具备网页、XPath 或区域语义。

**用文字摘要压缩图片历史。** 不能保证后续追问仍能读取原图细节。保留原图上下文并承担上下文上限；具有可验证的图片引用压缩机制后再重新考虑自动压缩。

## 验证

实现与验证记录见[图片聊天验证数据](../../../../docs/measurements/widgee-chat-images-2026-10-22.json)。真实模型读取五张卡片并在无新图片的追问中重复全部代码；杀死本地 Worker、复用持久目录重启后的 alarm 恢复完成，只有一条公开用户消息、两个执行 attempt。

真机 iPhone Air / iOS 27.0.1 覆盖五张选择、上限、移除补选、草稿重启、发送后重启及历史预览；[预览截图](../../../../docs/measurements/widgee-chat-image-preview-2026-10-22.png)显示实际处理版本。后端测试覆盖非法输入、实际流量限制、幂等、事务回滚、跨会话读取、删除与上传竞态；Swift 测试覆盖处理、恢复、缓存与迟到结果。可重复真实模型入口是 `npm run e2e:widgee-images`，运行条件见[开发指南](../../../../docs/development.md)。

## 后果

五张图片增加上传耗时、模型成本、存储和内存压力。五张 2048×2048 JPEG、合计约 6.4 MiB 的本地解码检查耗时约 0.86 秒；整进程 workerd RSS 约从 197 MiB 增至 701 MiB。该值包含本地运行时，不能当作生产 isolate 堆测量；尚未部署验证 Cloudflare 内存上限。PNG 膨胀和 JPEG 解码均设独立预算，但这些限制不能替代部署环境的容量测量。

2048px 缩放可能损失长截图的小字，因此发送前和历史均提供实际上传版本预览。含图片会话不自动压缩，长期追问可能达到模型上下文上限；明确失败比无提示地丢图更符合输入契约。

图片在会话存续期间保存在服务端，与聊天正文相同。声明式 userId 的身份限制由[Keychain 客户端身份](../../implemented/feature/2026-10-26-client-keychain-identity.md)拥有，图片不扩大该边界。纯图片发送、拍照和长期素材采用不属于本能力；会话内稳定标识为未来单独的素材采用方案保留空间。
