# Agent Note: 动态 Widget 每次刷新直接查询数据

Status: implemented
Archived: 2026-11-05

## 问题

健康参考和示例要求生成脚本保存查询值，可能让动态数据依赖手动同步或沿用旧值。晴日圆环还将全部健康查询的成功作为保存前提，一项无数据就阻断其他项。用户明确要求调整 prompt：需要定时更新的数据由 Widget 直接调用真实 API，不经过脚本数据缓存，桌面刷新交给 iOS。

## 决策

可复用图片素材的 storage 缓存例外见[图片搜索与缓存提示词](2026-10-30-widget-image-search-cache-guidance.md)；健康、天气等当前数据仍遵循本记录。

系统提示明确动态数据在每次 async widget 调用中查询受支持的真实 API，结果只供本次渲染使用；配置、凭据和用户操作产生的持久状态仍按现有规则保存。不得把 live 数据读取仅放在配置按钮或只执行一次的 App onAppear，也不从 storage 恢复健康、天气、行情等数值作为当前数据。

同步健康按需参考、SDK 说明和七日步数示例。独立数据项分别捕获失败，有可读值的项继续显示，无值显示不可用，不把错误变成真实零值。widget 通过 refreshAfter 请求刷新，不轮询或宣称严格实时。保留宿主画面与系统时间线缓存；本次不改变原生健康方法的可用范围、权限或错误返回契约。

本次仅改变后续模型生成规则，不自动修改已有服务端产物与用户已采用脚本。[四项健康直接读取](../../proposed/feature/2026-10-26-widget-direct-health-reads.md)继续拥有原生类型扩展和晴日圆环修订；其中模型生成规则由本记录拥有。[已授权步数预览](../../proposed/feature/2026-10-20-widgee-authorized-steps-preview.md)继续拥有已实现的只读桥接及未完成设备验收，其旧示例缓存指导由本决策替代。旧脚本和宿主回退仍存在，因此相关记录不归档。

## 曾考虑的替代方案

**每次查询并更新带时间的数据缓存。** 这种实现本身能更新，但增加缓存分支且可能被生成模型写成只从缓存加载；用户明确选择每次直接取数。

**只在系统提示增加一句规则。** 与按需健康参考及可复制示例冲突，不能可靠地改变生成行为，需同步所有模型入口。

## 验证

Node 示例测试 6 项通过，覆盖每次取新值、部分与全部失败、失败后重试、零值、accessory 和授权反馈；换回旧缓存示例时测试失败。WidgeeBridge 的 HealthStepsTests 4 项通过，其中真实 WidgetRunner 连续执行同一示例，证明新值更新、失败无旧值回退且不创建 storage.json。Chat 版本测试 29 项通过。

本地 Worker 的隔离会话使用真实模型生成七日步数脚本，完成后删除该会话。生成源码的 widget 每次调用 readWeek，逐日捕获错误，不调用 storage；执行该源码的四轮受控查询共调用 API 28 次、storage 0 次，验证新值、部分失败和全部失败。此检查不代表真机权限或 WidgetKit 调度验证。证据保存在本地 `.playwright-mcp/sunny-health/live-prompt/`。

合成 SYSTEM_PROMPT 的 o200k_base 计数从 10,204 增至 10,339，增加 135；这是不含工具 schema 和用户消息的 tokenizer 代理计数，不是网关模型的实际计费数。SDK 生成与一致性检查、类型检查通过。

## 后果

配置、凭据和用户状态继续持久化；动态 API 值不再需要脚本维护缓存更新时机。锁屏、权限或网络失败会使本轮部分数据不可用。iOS 仍可延迟刷新，直接查询不等于持续实时显示。提示词不能绕过 SDK 不支持的健康类型，也不能给已有作品自动替换源码。

Prompt 版本为 widgee-14。SDK 的健康说明参与内容哈希，因此本次文字变更也产生新 SDK revision；API 签名和运行时能力不变，兼容列表保留上一版产物读取能力。客户端与服务器会话的 SDK 匹配规则仍有效，部署服务器时需配套新版客户端。部署记录由 Beads 任务 webclip_widget-dnu 维护。
