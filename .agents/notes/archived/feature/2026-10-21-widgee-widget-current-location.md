# Agent Note: Widgee 桌面 Widget 按当前位置刷新

Status: implemented
Archived: 2026-11-05

## 问题

“双地点智能通勤地图”需要根据当前位置离 A、B 的远近选择 A → B 或 B → A。配置时保存的位置不能代表桌面刷新时的位置；移动后沿用该坐标会选择错误方向。定位还必须适应 Widget 的独立授权和有限执行时间，不能让无效或过期位置表现为当前结果。

## 决策

用户要求当前位置时，生成的 widget() 在每次实际刷新中显式调用 location.current，再计算方向和路线。固定 A、B 地点继续持久化；用户选择固定城市、固定起点时仍可保存坐标。maps.snapshot 本身不隐式定位。

扩展检查 isAuthorizedForWidgetUpdates，未授权时返回定位权限错误，不尝试弹授权框。首次定位授权由主应用完成，系统负责询问是否将权限扩展到 Widget；When In Use 即可，不为此要求 Always 权限。每个请求拥有独立 CLLocationManager 和 delegate，取消与完成只清理该请求，迟到回调不能完成后续请求。

Widget 接受测量年龄在 0 至 60 秒内、坐标与水平精度有效的样本，最多等待 3 秒。60 秒允许系统复用近期样本，3 秒给地图留出宿主 8 秒预算中的剩余时间；地图仍保留自己的 7 秒上限。主应用授权与定位等待分别最多 30 秒、15 秒。参数和调用职责由 [iOS 设计](../../../../ios/DESIGN.md#地图位图)维护。

定位拒绝、超时或没有足够新的位置时，脚本显示定位不可用，不用 storage 中的旧坐标决定当前方向。成功视图标注 CLLocation 的实际测量时间；宿主因整次运行失败保留旧快照时，旧定位时间保持不变。地图和路线失败如实显示，不伪造路径或 ETA。

模型通过 module:location 按需加载详细说明，module:maps 与 Widget 基础教材指向该参考。当前提示词版本与 SDK 兼容规则由[客户端协议](../../../../docs/widgee-protocol.md)维护。既有源码不会随教材自动改变：原通勤会话生成的新版本保留 commute.endpoints.v1 与满幅地图布局，通过现有显式添加／更新流程采用；服务端旧版本不可变，宿主不通过字符串替换迁移任意脚本。聊天真实配置、预览与离线 stub 的职责见[聊天配置草稿与真实预览](../../proposed/feature/2026-10-20-widgee-chat-saved-configuration-preview.md)。

本决策部分取代[地图位图 API](2026-10-20-widgee-map-snapshot-api.md)中保存用户位置供桌面读取的要求；该笔记的地图生成、归属标识、路线真实性和缓存理由继续有效。

## 平台依据

[Apple：Accessing location information in widgets](https://developer.apple.com/documentation/widgetkit/accessing-location-information-in-widgets)要求主应用授权、NSWidgetWantsLocation 以及 Widget 的定位许可。When In Use 下，Widget 可见后一小段时间内执行刷新时可以获取位置；获准定位不保证每次刷新都收到位置。WidgetKit 决定刷新时机，因此能力是“刷新时获取当前位置”，不承诺移动即切换、持续后台定位或实时导航。

## 曾考虑的替代方案

**只修改地图教材。** 可以让模型调用现有 API，但未处理扩展独立权限、过期位置和 15 秒定位等待超过 8 秒渲染预算的问题，不能作为完整交付。

**主应用持续定位并将坐标写入共享存储。** 增加后台定位与电量成本，且桌面仍依赖此前写入的位置；用户要求直接定位，因此不采用。

**定位失败时静默读取已保存坐标。** 可提高地图出现率，却可能选择错误的通勤方向；当前通勤模式不采用这一回退。固定地点模式不受影响。

## 后果

当前位置决定路线方向，固定端点决定路线起止位置。定位不持久保存、不上传到生成服务器；地图服务仍需接收计算路线所需的坐标。旧脚本只有显式采用新版本后才获得刷新定位能力，不自动覆盖其他已采用 Widget。

3 秒等待和 60 秒有效期以有限预算内的近期位置为目标，不保证新的 GPS 测量。室内、粗略定位和网络延迟可能降低成功率，A、B 很近时定位精度也可能不足。若后续真机证据要求调整阈值，应重新评估位置时效与地图预算，不能静默放宽为任意历史位置。短期测试不证明长期系统调度可靠。

## 验证

WidgeeBridge 的 10 项测试通过，覆盖未授权时不弹框、有效期边界、无效精度、独立取消与迟到回调、3 秒超时及主应用授权。可控位置分别靠近 A、B，检查参考示例与真实生成脚本在三种尺寸下选择相反路线；任何读取已保存位置的尝试都会失败，拒绝和过期结果均显示不可用。超时和过期样本由注入测试覆盖，未通过人为制造真实 GPS 故障验证。

原通勤会话的新版本为 3501d500-4ad2-48a5-af6a-79e6dcbafd1a，未经手工改写的模型输出保存在 [commute-current-location.js](../../../../backend/src/widgee/fixtures/commute-current-location.js)。SDKTeachingTests 的 6 项常规测试通过，包含该样本完整生命周期与三种尺寸；1 项需显式启用的在线生成测试跳过，真实模型生成另由原会话完成。首轮主提示词以 o200k_base 测得从 10,194 增至 10,204 tokens，详细定位参考按需加载；该数字不是服务商计费统计。

iPhone Air 的实际桌面扩展取得年龄 0.788 秒的位置，并生成预计 610 秒的真实路线；存储中的请求标记与本次刷新一致，桌面截图与 UI 测试通过。拒绝权限后的新刷新返回 Widget 未获定位授权，桌面显示“桌面定位不可用”，同样通过请求标记、原生断言和截图核对，未沿用旧成功结果。恢复权限后重新取得年龄 0.975 秒的位置与预计 606 秒的路线，桌面和原生核对通过。真机验证入口及权限恢复要求见 [iOS README](../../../../ios/README.md#真机详情页测试)。
