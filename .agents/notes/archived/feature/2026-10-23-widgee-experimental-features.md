# Agent Note: iOS 实验功能编译开关

Status: implemented
Archived: 2026-11-05

## 问题

部分客户端功能需要由构建者选择是否提供。详情页分享需要可关闭的入口，同时保留可供验收的开启版本。

## 决策

`WIDGEE_EXPERIMENTAL_FEATURES` 使用编译期选择，Debug 与 Release 均默认关闭；启用方式由 [iOS 构建说明](../../../../ios/README.md#实验功能编译开关)拥有。独立于 `DEBUG` 的条件允许调试构建隐藏功能，也允许发布构建显式开启。

`RunnerView` 只对分享按钮使用条件编译。分享状态、确认页和提交逻辑保持原有实现；启用按钮后仍需满足非草稿、资料库 Widget 与成功预览约束。后续功能可选择接入同一条件。

[广场分享决策](2026-10-22-widget-gallery-sharing-moderation.md)继续拥有提交、审核与采用，本记录拥有入口的构建可用性；两篇保留活跃，无归档或删除。

相关决策：[Shared Widget 中英文内容与缩略图](../../implemented/feature/2026-10-23-shared-widget-localization.md)提供共享内容的语言生产与读取，入口继续受本记录的实验功能开关控制。

## 曾考虑的替代方案

**直接复用 DEBUG。** 调试信息与可选产品能力需要独立选择，因此使用单独条件。

**运行时偏好开关。** 用户要求按编译选择入口，运行时设置会额外引入持久化与交互语义。

**同时条件编译状态和确认页。** 用户要求先做仅屏蔽按钮的简单版本，因此将条件限制在入口。

## 验证

关闭、开启两种真机 Debug 构建均成功；两份 App 二进制中的 `widget-share` 标识分别缺失和存在。Debug/Release 的默认与开启共四组构建设置验证了条件选择，并确认 Debug 保留原有 `DEBUG`。iOS 静态门禁 24 项、文档与 Notes 门禁通过。SwiftLint 对比基线仍有相同两项既有告警，没有新增告警。

开启版已以原 App 与扩展签名身份安装到连接的 iPhone 并成功启动，资料库、8 个源文件、服务地址与用户设置保持一致。本次未重新执行分享提交或模型调用验收；入口内的逻辑没有改变。

## 后果

普通构建没有详情页投稿入口，广场分享 UI 验收需显式开启。条件只控制接入的客户端入口，不代表整个分享模块从二进制移除，也不提供后端授权。后续接入的功能会随同一开关一起开启。
