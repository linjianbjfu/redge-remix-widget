# Agent Note: 音乐技能收集多首音源并随机播放

Status: implemented
Archived: 2026-11-05

## 问题

用户请求“帮我创建一个音乐 widget，播放周杰伦的歌”时，模型仅调用一次 kind: artist，所有平台返回无可用直链后停止。用户随后指定《晴天》，kind: song 找到了可播放的 Live 版本。歌手候选不能直接解析不等于按歌名搜索也不可用；缺少候选目录和过早停止让模型把选曲工作交回给用户。

用户明确要求先列出歌手歌曲，多次按歌曲搜索 URL，汇集一批音源，再生成随机播放 Widget。

## 决策

[search_music](../../../../backend/src/widgee/music-search.ts)增加 artist_tracks 模式。该模式只搜索歌手候选，返回歌名、歌手、平台和 ID，不以直链解析成功为前提。每页每平台最多十条，返回可继续请求的 nextPages，页码为 1–10；搜索候选不代表完整曲库。现有 song 与 artist 模式保留。

[network-music](../../../../backend/skills/network-music/SKILL.md)及[选曲参考](../../../../backend/skills/network-music/references/selection.md)使用中文说明两阶段流程。对于未限定单曲的歌手播放请求，先列候选，再逐首搜索，目标收集 3–5 首不同歌曲的已验证 HTTPS URL；单首或单个平台失败继续其他候选。常规流程最多尝试八个不同歌名，避免无限搜索。用户明确只要一首时保留单曲流程。

至少两首时可生成随机播放、歌单展示和手动切歌 Widget；只有一首时如实提供单曲播放，不伪装成多首随机。已有歌手信息就足以开始，不要求用户补充可以搜索得到的歌名。Live 等版本保留真实名称，对用户限定版本不擅自替换。

生成脚本保存静态曲目数组，在显式用户动作中随机选曲并调用 audioPlayer.play；多首时排除当前索引，避免紧邻重复。选择可写入 storage 供重建显示，实际播放状态仍由 getState 提供。此流程复用已有播放器，没有增加原生自动连播、后台搜歌或自动续签 URL 的保证。

生成器版本为 widgee-19。技能目录按内容摘要形成路径；系统提示词要求当历史技能的路径与当前目录不同时重新读取，即使旧正文还完整保留在上下文中。旧会话不会仅因缓存了旧限制就继续执行一次选曲策略。

[内置 skills](2026-11-02-widgee-native-generation-skills.md)继续拥有资源加载、受限读取与 Pi 集成；[后台音频](2026-11-02-widget-background-audio-player.md)继续拥有播放器、单音源与生命周期。本记录改变音乐选曲工作流，不完全取代任何活跃记录。

## 曾考虑的替代方案

**反复调用 artist。** 同一页直链候选可能反复失败，模型仍拿不到歌名，无法形成用户要求的两阶段搜索。

**仅修改技能，让模型凭记忆猜歌名。** 对知名歌手可能有效，但接口已经提供实际候选，先列目录更可检查，也适用于不熟悉的歌手。

**在 App 每次点击时在线搜歌。** 用户要求后端生成时取得一批 URL，现有原生 API 也不提供该搜索工具。静态音源池可以直接复用播放器。

## 后果

多轮搜索增加模型与上游请求成本，技能限制候选尝试数量并报告实际收集的数量。没有可用 HTTPS 音源、版本不匹配或 URL 过期时仍可能无法播放，不通过 Cookie、音频代理或全局 HTTP 例外掩盖失败。

相同简单请求下，工具与技能目录的首轮输入从 11,442 增至 11,570 tokens，增加 128；技能全文仍按需读取。多轮歌曲查询的总输入成本随实际尝试次数变化。

平台只返回有限候选，因此不能宣称已搜索歌手所有作品或进行全曲库均匀随机。随机范围是生成代码中的已验证曲目列表。每首歌的多个版本不能用来虚增歌曲数量。

## 验证

2026-11-03 先用用户本地会话记录确认：artist 返回空后停止，随后用户指定《晴天》的 song 搜索成功。新增回归在旧实现中失败，支持目录模式后通过：直链不可用时仍能取得歌名，再通过 song 找到可播放版本。

验证结果：

- 音乐搜索 35 项和原生 Chat 29 项通过，覆盖目录／分页／候选过滤、部分失败、取消、旧模式与直链校验。随机选择示例覆盖空池、单曲、多曲和紧邻不重复。
- 独立 workerd 技能测试、技能打包门禁 11 项、Agent/Pi 集成 11 项、类型、SDK、文档和 Notes 检查通过。
- 原始请求真实生成成功：先 artist_tracks，再分别搜索《晴天》《青花瓷》《夜曲》《稻香》，生成包含四个已验证 URL 的随机切歌 Widget。旧技能上下文恢复场景也重新读取当前版本并生成多首音源池。
- 单曲、计数和普通问答真实模型回归通过；后两者没有读取音乐技能或搜索音乐。
- 生成产物的四条 URL 分别通过 iPhone 原生播放启动检查。带状态诊断的实际 Widget 测试观察到随机切歌从索引 2 切到 0、原生 playbackId 改变，随后暂停成功。

首轮真机随机切歌测试曾报告测试缓存目录不存在的 NSCocoaErrorDomain Code 4；当时已经进入音频流程，异步行号不能证明失败发生在保存阶段。增加诊断后未复现，未修改产品代码，也未将重试视为修复；该异常保留为 Beads webclip_widget-5kx 继续调查。证据位于本地 `.playwright-mcp/music-pool/`。
