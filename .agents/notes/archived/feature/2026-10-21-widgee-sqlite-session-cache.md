# Agent Note: Widgee SQLite 会话缓存与增量同步

Status: implemented
Archived: 2026-11-05

## 问题

重复打开聊天需要逐页扫描服务端持久化事件，其中大量内部条目不展示。只有本地游标而没有对应消息，不能安全跳过历史；内存列表和重复下载的源码也不能改善冷启动。远端删除必须同步到手机，但 offset 分页在并发新增、删除时可能漏项，不能把列表缺项当作删除证据。

## 决策

服务端拥有会话、正式消息、生成状态和不可变产物；主应用以系统 SQLite3 保存可重建读缓存，先显示最近 100 条消息/产物，再从已提交 cursor 增量同步。较早消息从本地分页读取，保留阅读锚点。缓存不上传历史、不执行生成工具，也不支持离线排队生成。

接口与错误语义由 [Widgee 协议](../../../../docs/widgee-protocol.md)维护，组件归属和容量由 [iOS 设计](../../../../ios/DESIGN.md#后端通信边界)维护，验证命令由 [iOS README](../../../../ios/README.md)维护。

### 两种独立的同步位置

会话目录采用追加式 create/update/delete change log，而消息、标题和生成状态沿用单会话历史 cursor。日志行不会在分页期间移动，不需要 offset 或 through 上界；每页最多 100 条，响应 version 只覆盖实际返回的日志。正式业务更新批次追加一次 update，内部条目和临时增量不写目录日志。目录 update 同步未打开会话的摘要，客户端按服务端更新时间排序；机制及取舍见[更新时间排序](../bug-fix/2026-10-22-widgee-session-update-order.md)。

创建/删除与目录日志在同一服务端事务提交，通用 Store 删除入口遵守同样规则；存量会话只回填一次。create/update 所指实体已删除时返回 null 摘要并保留日志位置，后续 delete 仍能到达长期离线客户端。客户端同页变更与 version 原子提交，不因缺项推断删除。Chat 可见时每 30 秒补同步，进入前台、打开抽屉和手动刷新也同步；重复请求合并，每次最多处理 20 页，持续创建时从已提交位置继续。

epoch 区分服务器重建/恢复后的代际，正常部署和重启保留它。代际重放完成前保留旧缓存，完成后切换并清理缺失会话；历史 cursor_ahead 只重建受影响会话。代际变化保留待确认发送的文字与图片文件引用并要求人工核对，不能向可能失去幂等记录的服务端自动重发。恢复服务端备份必须更换 epoch；未来截断目录日志也必须配套完整重建协议。

### 原子发布与任务归属

消息、摘要、源码引用和历史 cursor 在一个 SQLite 事务提交后才发布到 UI。空历史页也推进扫描游标；checkpoint 只推进位置，text_delta、心跳和 stream_end 不持久化。未知正式事件拒绝提交，避免游标越过客户端不能解释的内容。同会话恢复也重新发布已提交快照，防止提交完成但 UI 发布被取消后永久漏行；已展开的本地阅读范围保留。

数据库由专用串行执行器持有，SQL、编解码和哈希计算不在 MainActor 执行；使用 WAL、FULL 同步、受保护且排除备份的主应用目录。缓存身份包含规范化服务地址及客户端 userId，保留协议、端口和业务路径差异，编码斜杠不等于路径分隔符。[Keychain 客户端身份](../../implemented/feature/2026-10-26-client-keychain-identity.md)拥有 userId 的 Keychain 来源；缓存继续按服务与身份隔离。只对确认损坏或不支持的 schema 重建，磁盘满、锁定或暂时无法访问不得触发删除。

每个会话只有一条历史/订阅写入链，页面追齐后沿用既有 SSE 恢复协议。身份、选择和缓存重建的任务代次阻止迟到响应覆盖当前页面。源码按会话/版本保存并验证长度、SHA-256 和 SDK；预览、配置、采用共用读取入口，同版本下载合并。产物 404 不代表会话删除，只有明确 session_not_found 或 delete 日志触发会话清理。

### 缓存与用户数据分开

输入草稿、PendingChat 和 ChatDraftStore 配置保留原有存储归属，不能随可重建数据库损坏或淘汰丢失。规范化缓存身份记录已知原始草稿身份别名，便于删除时清理，不静默迁移配置。旧的独立 UserDefaults cursor 没有消息副本，不作为新缓存的恢复位置。[图片输入](../../implemented/feature/2026-10-22-widgee-chat-image-input.md)扩展附件草稿与图片缓存，继续沿用用户数据和可重建缓存分离的规则。

确认删除时同一事务保存删除标记、移除消息、图片与源码并加入 cleanup_jobs；停止订阅、预览及配置运行后清理草稿文件、输入和 Keychain，失败跨重启重试。删除标记阻止迟到历史、下载和已打开配置页重建会话。本机删除必须先得到服务端成功或明确 session_not_found；离线失败不加入延后删除队列。已采用 Widget 的源码、配置、快照与正式 Keychain 是独立副本，保留不变。

每个身份消息、图片与源码有效载荷上限为 100 MiB，图片与源码共享 50 MiB 子缓存。先淘汰 LRU 图片或源码，再整份淘汰未使用的会话历史并归零 cursor，保留摘要和用户数据。当前历史受租约保护；单会话超预算时标为不持久保留，释放后整体清除，重开从 0 获取。SQLite 索引和 WAL 不计入载荷预算，空闲时检查点和增量回收。

本记录部分替代[原生聊天](2026-10-19-widgee-widget-chat.md)的本地历史策略和[长生成连接恢复](../bug-fix/2026-10-21-widgee-sse-idle-recovery.md)的游标提交方式，保留服务端权威、同 turn 幂等和有界恢复；扩展[聊天配置草稿](../../proposed/feature/2026-10-20-widgee-chat-saved-configuration-preview.md)的远端删除清理。这些记录仍约束独立行为，保持活跃。标题、真实联网预览与渲染语义仍由[标题与预览](2026-10-19-widgee-chat-title-preview.md)和[联网预览](2026-10-20-widgee-chat-network-preview.md)维护。

## 曾考虑的替代方案

**只缓存内存或 JSON 文件。** 内存不能改善冷启动；JSON 可以保存快照，但多会话增量、唯一 seq、源码淘汰及消息/游标原子更新更适合 SQLite。

**完整拉取 offset 列表后删除本地差集。** 并发写入可使分页遗漏记录，存在误删风险。逐个请求缺失 ID 确认可避免误删，但仍需要全量目录与额外请求，因此采用显式创建与删除日志，正式更新通过 update 日志扩展。

**按 updatedAt 拉取，删除立即物理清空。** 时间戳相同、时钟变化和删除记录缺席都无法可靠推进；使用单调版本及删除标记。

**每个会话只保留最新变更。** 分页期间版本会移动，需要 through 上界和延后补读。追加式日志可以直接按 version 前进；创建、正式业务更新与删除共用追加日志；正文仍使用独立 session cursor。

**SQLite 同时保存输入草稿、配置与预览截图。** 这会混合可重建缓存和未同步用户数据，增加恢复、淘汰及隐私数据生命周期复杂度。草稿保留原有归属，源码独立缓存；预览截图只有在实际渲染测量表明必要后才另行设计，需包含时间、配置指纹和过期显示。

## 验证

通过的检查包括 `npm run typecheck`、后端聊天/目录日志/Store/DO 的 58 项测试、`npm run test:chat-cache` 的 18 项宿主测试、34 项真机缓存/同步/草稿/导航/连接/滚动测试，以及 17 项连接集成测试。真实模型生成中断开后恢复，服务端保持一个 attempt；性能样本不调用模型。移除消息/游标事务、删除标记、目录版本保护或同会话已提交消息发布的四个负例都被行为测试拒绝。Simulator 与签名真机 build-for-testing、SwiftLint strict、verify-ios、verify-docs、verify-notes 通过。

真机 UI 在冷启动后挂起历史网络响应，验证缓存可读、滚动、草稿编辑、发送等待追齐、刷新保持阅读位置；独立删除后刷新和重启均不再显示会话。设备 HTTP 测试另覆盖删除时迟到的历史响应；草稿测试验证 Keychain 清理与已采用副本保留。宿主使用显式 ChatDraftStore 替身，不替代真机文件/Keychain 证据。

iPhone Air（iOS 27.0.1）以局域网隔离 Worker 跑 10 轮/5 产物、100 轮/50 产物，每轮包含 8 条不展示的 pi 条目。每种首次打开、缓存重开和缓存冷启动各五次，全部 30 个样本通过。下表耗时为中位数 / 最慢值，单位 ms：

| 轮数 | 场景 | 可见帧 | 追齐 | 历史请求数 |
| --- | --- | --- | --- | --- |
| 10 | 无缓存首次打开 | 180.9 / 247.9 | 229.3 / 328.3 | 3 |
| 10 | 缓存重开 | 67.5 / 69.5 | 291.4 / 418.0 | 1 |
| 10 | 缓存冷启动 | 48.7 / 101.1 | 154.4 / 278.6 | 1 |
| 100 | 无缓存首次打开 | 335.3 / 420.4 | 1085.2 / 1168.6 | 23 |

可见帧从 ChatModel.open 到消息进入可见范围后的第二个 CADisplayLink 回调，表示布局后的显示机会，不是屏幕物理扫描或完整启动耗时。缓存样本均低于 300 ms 目标；无缓存是同一实现的空缓存状态，不是旧版本二进制基线。10 轮缓存重开的联网追齐中位数高于其无缓存样本，说明网络抖动仍会影响状态确认，不能以本地显示速度保证联网追齐速度。

100 轮无缓存窗口内下载约 228 KB JSON，缓存重开为 544 B、冷启动为 458 B；统计包含目录和实际发生的预览下载。缓存样本最大主线程帧间隔为 70.8 ms，常驻内存最高约 122.7 MiB；这不是峰值内存或持续滚动帧率。100 轮缓存的 SQLite 为 352,256 B，缓存重开/冷启动的 WAL 最高为 45,352 B，SHM 为 32,768 B。所有指标的原始样本、中位数、最慢值及计时边界见[测量数据](../../../../docs/measurements/widgee-chat-cache-2026-10-21.json)。

功能 UI 与 30 样本性能 UI 在同一最终真机构建中通过。一次先前诊断运行因系统通知打断测试控制文字输入而失败，其 29 个完整样本也保留在数据文件中，不计入验收统计。最终控制使用固定操作按钮，不重试请求或放宽超时。真实天气/地图 API 就绪时间、物理显示扫描、启动全程和峰值内存未测量。

## 后果

[中英文界面](2026-10-23-widgee-ui-localization.md)按当前 App 语言展示缓存中的系统默认标题和已知错误，保留本记录的缓存身份、版本和原子提交规则。

缓存减少重复历史和源码下载，但新增本地持久化与同步状态复杂度。事务、独立版本和任务代次共同防止游标领先数据、旧响应覆盖新状态及删除后重建；不能以页面取消替代持久化一致性。

远端删除是成功联网后的最终一致性，离线时仍可能展示旧内容。聊天正文和源码扩大本地持有的数据范围；缓存排除备份，不额外复制真实健康/地图返回值，也不改变服务端现有 声明式 userId 的信任限制。

首次全量加载仍采用正向历史协议。超预算重新加载、真实 API 和 Widget 渲染可能较慢；缓存不提供预览截图、离线生成或后台永久同步。首屏可读与预览完成是两个终点，不能用缓存时延承诺天气/地图画面立即就绪。
