# Agent Note: Widgee 详情页尺寸选择与可选配置页

Status: implemented
Archived: 2026-11-05

## 问题

“我的 Widget”的尺寸只能通过长按卡片修改，进入详情页后不能切换。喝水 Widget 的详情同时显示顶部 Widget 预览和脚本的完整喝水页面，重复展示标题、计数和按钮。顶部目前不接受交互，直接移除下半页会丢失“喝一杯”的可用入口。

## 决策

详情页在 Widget 上方提供“小／中／大”分段选择，初始值来自已保存的 preferredFamily。按所选 family 重新渲染，成功后保存偏好并更新列表快照；失败显示错误并保留上次有效尺寸与画面。连续切换只采用最后一次选择的结果，不重启正在编辑的配置表单、不丢失未保存输入。关闭再打开和冷启动均保留选择。主屏幕 Widget 的实际尺寸继续由 iOS 决定。

为纯 Widget 支持省略 render()：有 widget() 且未提供 render() 时，详情只显示尺寸选择和 Widget，不显示“无需设置”占位文字，也不创建全高的脚本页面。提供 render() 时仍要求返回有效视图，undefined、null 和异常不能被吞成“无需配置”。没有 widget() 的普通应用仍必须提供 render()。运行时、采用校验、模型参考和 SDK 版本同步支持这项声明。

纯 Widget 详情使用与桌面相同的 WidgetRunner 渲染和执行 Button／Toggle 操作；点击“喝一杯”会真实保存数据，然后从共享 storage 重新生成当前尺寸画面、列表快照并请求桌面刷新。操作串行执行，防止重复提交；切尺寸、退出或换源码后拒绝迟到结果。配置表单模式沿用活动 Host 投影，顶部保持静态，避免桌面操作覆盖表单草稿。详情宿主指定 MiniAppView 内容顶部对齐并与预览间隔 16pt，脚本内边距另算；普通应用保留默认居中。聊天和资料库缩略图仍不可交互。

生成提示词与教学示例区分两种产物：喝水等只有 Widget 内操作的脚本省略 render()；倒计时、地点、授权等需要应用内配置的脚本只生成配置表单，不调用 Widget 布局函数或重复显示标题、计数、进度和操作。运行状态不等于用户输入配置，固定目标计数器无需表单；可编辑目标才需要输入及保存。必要的定位／授权按钮不因没有输入框而省略。该规则同时用于新建与会话修改，修改保留存储键、用户配置和有效操作。当前提示词保留这些配置表单规则，版本与兼容升级规则见[客户端协议](../../../../docs/widgee-protocol.md)。截图中的“喝水 QA-E1D142”在核对源码后改成纯 Widget，保留 ID、storage、云端来源和现有杯数，不按是否包含输入框、中文文案或视图位置批量裁剪用户脚本。

本方案扩展[资料库尺寸偏好](../../implemented/feature/2026-10-19-widgee-tabbed-chat-library-ux.md)，并部分调整[配置与 Widget 刷新](../../implemented/bug-fix/2026-10-19-widgee-configuration-widget-refresh.md)的详情交互边界：只有纯 Widget 详情启用操作，配置表单的隔离投影规则保持有效。两篇仍拥有独立决策，保留活跃；本提案不取代或归档它们。

## 曾考虑的替代方案

**根据没有 TextField 自动隐藏下半页。** 截图中的喝水页有按钮，天气也可能只提供定位或授权按钮；没有输入框不代表没有必需操作。宿主不能据此删除页面。

**删除下半页并继续使用静态预览。** 会使喝水计数等操作在详情中不可用，因此需要同时提供真实 Widget 操作。

**用 render() 返回 null 表示无需设置。** 会把常见的遗漏返回值与合法空页面混在同一路径。显式省略函数能保留已有 render() 返回值校验，也允许纯 Widget 直接使用桌面运行路径。

## 后果

脚本生命周期允许没有应用页面，旧客户端不认识纯 Widget 产物；SDK 哈希随之变更，服务端拒绝向不匹配的客户端生成新格式。既有含 render() 的脚本继续展示其页面，只有明确修改源码才去除配置页。

Widget 操作可能访问网络或权限，应复用桌面模块限制并展示失败，不把静态预览按钮当成成功执行。WidgetKit 仍可能延迟刷新。尺寸偏好不创建新副本，也不能修改已放置桌面实例的尺寸。

## 验证

服务端 28 项测试、类型检查、Swift Package 62 项测试、iPhone Air 的 12 项单元／集成测试通过。覆盖非法生命周期、保存失败、迟到结果、重复操作拒绝、操作错误在存储刷新后仍可见，以及配置处理器与草稿保留；异步竞争使用 barrier 确定时序。SDK 产物、iOS 契约及负例、文档与 Notes 门禁通过，应用层变更和真机测试的 SwiftLint strict 通过。

三项真机 UI 测试通过：喝水详情只有一个可操作 Widget，三种尺寸与冷启动保存正常；倒计时未保存输入不因尺寸切换丢失；详情内喝水后，已选择该脚本的主屏幕 Widget 显示更新计数。截图已核对。指定喝水脚本仅移除 render()，身份、来源、每日计数逻辑不变，测试杯数已恢复；所有原资料库尺寸保留。真机入口及测试副作用见 [iOS README](../../../../ios/README.md#真机详情页测试)。

测试助手断连和元素定位失败的轮次不计为通过。真实天气服务授权仍有独立的未完成验收。

widgee-8 提示词按字符数 / 4 估算从 9,169 增至 9,375 tokens（不含工具，非模型账单 token）。后端 28 项测试、3 项真实 pi 接入测试、类型检查及 6 项 Swift SDK 教学测试通过，包含真实生成源码路径。真实模型经本地 HTTP/SSE 服务完成固定目标喝水创建、改目标和颜色、增加目标配置及普通聊天；三个不可变版本下载与哈希核对通过。前两版没有 render，第三版只有目标 Stepper、保存按钮和反馈，没有重复 Widget；三版均通过原生运行时与三个 Widget family 的有效性检查。给教学示例临时加入计数页面或重复的配置预览会使对应 Swift 测试失败，恢复后通过。

iPhone Air 部署通过，`test-chat-device.sh` 限定运行的 5 项 WidgetDetailTests 和 1 项真实模型 ChatE2ETests 通过。UI 流程验证生成、断线恢复、采用、三种尺寸、计数持久化、无配置页时只有一个计数和按钮；同一会话增加目标输入后，配置表单不重复计数或喝水按钮，保存 12 杯目标后预览更新且冷启动保留。截图已核对。UI 测试在冷启动后从历史重新选中原会话继续修改；未选择会话造成的失败轮次不计为通过。该有限样本不保证所有生成结果均符合布局规则，也不包含本轮主屏幕 WidgetKit 调度验收。

配置间距另由 ConfigurationLayoutE2ETests 在已有喝水目标脚本上验证，不调用模型。居中布局的负例实测间距约 204pt，超过 48pt 上限而失败；修复后小、中、大三种尺寸均为 30pt（宿主 16pt 加脚本 14pt），输入值保持、保存按钮可见，原尺寸恢复，5 项详情单元测试与该 UI 测试通过。
