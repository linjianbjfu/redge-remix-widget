# Agent Note: Widgee 原生生成的内置 skills

Status: implemented
Archived: 2026-11-05

## 问题

用户需要仅为 Widgee 原生 Widget 生成接入仓库内置、随后端部署的 skills。首个 network-music 需要基于用户提供的 music-url-demo.mjs，按歌曲或歌手找到可播放 URL，再生成调用 audioPlayer.play(url) 的 Widget。完整工作流应在音乐 Widget 需求出现时加载，不常驻每轮上下文。

Pi coding-agent 0.82.1 自带技能目录与显式命令，但原生链路缺少 read。Pi 的 `/skill:name` 直接调用 readFileSync，单独注入虚拟 Skill 路径不能完成正文加载；Workers 的请求级 `/tmp` 又不能依赖 isolate 的初始化标记。

## 决策

[多首音源与随机播放](2026-11-03-network-music-track-pool.md)记录用户授权扩展的歌手候选搜索与生成脚本选曲；通用技能加载机制继续由本记录拥有。

产品技能源由 [backend/skills](../../../../backend/skills/)拥有，与开发 agent 的 `.agents/skills/` 分开。[打包器](../../../../backend/scripts/widgee-skills.mjs)生成确定性 JSON，原生生成器通过 skillsOverride 注入 Pi 目录，保留 noSkills: true 关闭开发机／用户目录扫描。网页生成器不注册这些技能或音乐工具。

### 资源与请求生命周期

每份技能是名称与目录一致的 SKILL.md，可附 `.md`、`.txt`、`.json` 参考资料与模板。frontmatter 要求有效 name 和 description；disable-model-invocation 控制自动目录可见性。打包拒绝重名、符号链接、非法路径、无效 UTF-8 和非文本资源。正文最多 32 KiB，总包最多 512 KiB，限制显式调用的上下文量与请求初始化成本。

技能元数据、文件内容和内容摘要静态打包，不包含会话、凭据、用户标识、时间戳或随机目录。开发启动和部署前生成资源包，顶层 check 验证源与产物一致；维护步骤见[开发指南](../../../../docs/development.md#widgee-内置-skills)。

[加载器](../../../../backend/src/widgee/skills.ts)每次创建原生会话都将常量文件写入当前请求的 `/tmp/widgee-skills/<摘要>/`。后续请求、并发会话和恢复重建都重新准备相同版本的文件，避免错误复用上一请求的 `/tmp`。初始化失败使生成失败，不假报技能可用。

只读 read 复用 Pi 的行范围和截断能力，operations 将规范化路径映射到资源包中的精确文件。它不回退到通用文件系统，不访问用户数据、DO 工作区、其他 `/tmp` 文件或开发机目录。相对参考以技能目录解析；缺失／越界资源明确拒绝。正文与文件内容来自同一资源包，自动 read 与显式命令不会读到两套版本。

### 自动选择与历史

系统提示词只包含可见技能的名称、用途和路径；模型匹配任务后读取正文。network-music 用于创建音乐播放 Widget 或更换其选曲，普通音乐问答、天气和计数不加载它、不搜索音乐。选择由 Pi 中的模型根据意图和上下文完成，没有额外分类模型或关键词路由，因此不承诺确定性触发。已有完整正文可复用，压缩后缺失内容重新读取。

用户可输入 `/skill:network-music <需求>`，由 Pi 从当前请求的文件展开正文；隐藏自动调用的技能也可显式使用。没有 iOS 技能目录或补全界面。未知命令沿用 Pi 的普通文本行为。

公开历史保留用户原始消息，技能正文与 read 结果仅进入私有 Pi 上下文。技能和音乐工具不改变候选暂存、成功提交、取消及 attempt fencing。当前部署的技能目录用于新轮和恢复，旧工具结果按原历史恢复；提示词要求重新获取缺失正文，旧正文路径与当前目录不同时也必须重读。生成行为版本为 widgee-19；iOS JavaScript API 和 SDK revision 保持独立。

### 网络音乐搜索

[network-music](../../../../backend/skills/network-music/SKILL.md)指导模型明确歌手／歌曲、调用搜索、核对版本，再读取现有 SDK 参考并提交代码。未指定必要选曲条件时先澄清，不把参考脚本的默认歌手名单当作全曲库。技能不复制 audioPlayer 或 Button 的签名；[SDK 参考](../../../../backend/src/widgee/reference.ts)仍是生成 API 的权威。

[search_music](../../../../backend/src/widgee/music-search.ts)是后端专用工具，参数为 kind（song／artist／artist_tracks）、query、可选 platforms 和目录页码 page。它不能在生成的 JavaScript 中调用。provider 适配来自用户参考脚本，生产逻辑由 [music-providers.ts](../../../../backend/src/widgee/music-providers.ts)独立持有，不依赖根目录的未跟踪文件或 CLI 执行入口。

歌曲搜索在每个平台的前十个候选中按关键词匹配，最多返回各平台首个可播放结果；按歌手搜索只匹配歌手字段，包括合唱名单，在去重后的有限候选池中洗牌并选择首个可播放结果。保留 source、id、name、artist 和 url，Live、翻唱或不同版本不得冒充用户指定录音。随机候选不代表完整曲库或全曲库均匀抽样。

artist_tracks 只列候选、不要求直链成功，模型可据此多次按歌名搜索并形成静态音源池；具体选曲与随机播放策略由[多首音源记录](2026-11-03-network-music-track-pool.md)拥有。

平台接口固定为酷我、酷狗与 QQ，允许有限的同平台域名跳转。单次请求 10 秒、整体 30 秒，并连接 turn 取消信号。JSON 响应有界，平台失败互相隔离，返回有界错误码，不带底层正文或凭据。一般外部数据 API 由独立的 [API 响应探查工具](2026-11-04-agent-http-request-tool.md)提供，音乐搜索仍使用专用工具；原生生成器不提供 shell、Python 或 Node 子进程工具。

首期不读取平台 Cookie。返回音源必须是受支持平台域名下的 HTTPS URL，无用户名、密码或非标准端口；每次媒体跳转重新验证。探测不附 Cookie／Referer，只读取 MP3 前缀后关闭响应体。HTTP 音源明确不可用，不通过改写协议或修改 App 全局传输策略伪造成功。没有结果时技能要求说明失败，不生成虚假音源。

搜索发生在生成阶段。Widget 使用 URL 调用 audioPlayer.play，通过显式 audioPlayback 按钮控制，并用 getState 展示状态；播放由 App 持有。后端不代理持续音频，不自动更新过期 URL，不新增客户端搜歌 API。

## 曾考虑的替代方案

**只将 noSkills 改为 false。** 默认扫描不会把仓库技能自动变成 Worker 文件，也不能补上原生链路缺失的 read。

**只返回虚拟路径。** Pi 显式命令直接读文件，没有对应文件就不能加载。每请求准备常量文件保留 SDK 原生调用机制。

**另写 get_widgee_skill 与命令解析器。** 可以从内存返回正文，但需要重复维护目录提示和显式命令。请求内文件准备已在 workerd 验证可用，复用 Pi 即可。

**把全部技能正文常驻提示词。** 所有任务都会承担无关工作流成本，失去按需加载收益。

**只在技能中写接口，或直接运行 music-url-demo.mjs。** 技能文字不能执行搜索，参考脚本也没有对应的脚本执行环境；专用工具可以统一输入校验、取消、超时和有限输出。

**开放完整文件／脚本执行工具。** 超过读取常量技能和执行明确搜索所需的能力，扩大工作区、运行环境及维护范围。第三方执行型技能需要先适配现有工具。

## 后果

技能来源固定为仓库，没有用户上传、在线安装或按用户持久化。资源目录接口可复用给后续来源，但不会自动增加原生 API 或模型工具。每次影响行为的技能改动需要更新生成器版本与相关用例。

第三方接口可能变更、限流、缺少授权或只给出 HTTP 音源。MP3 前缀验证不保证整首曲目、永久有效或从所有手机网络播放成功。当前不提供平台登录、音乐代理、全曲库随机或过期 URL 自动刷新。

常驻目录和工具会增加首轮输入。相同系统提示词与简单用户请求对照中，禁用技能与新增工具为 11,028 tokens，启用后为 11,442，增加 414 tokens；正文未进入常驻提示词。该比较隔离目录与工具开销，不是旧版本整体性能基准。

## 验证

2026-11-03 的验证包括：

- 技能打包门禁 11 项，覆盖确定性、源／产物漂移、元数据、重名、路径、符号链接、内容预算和编码失败。
- 音乐适配器 31 项、原生 Chat 29 项、共享 Agent/Pi 集成 11 项。
- 独立 Wrangler/workerd 请求验证请求级文件隔离、同请求并发初始化、受限读取及行范围、可见／隐藏技能的真实 Pi 显式展开、初始化失败和后续请求恢复；网页技能目录为空。Vitest 直接加载完整 Pi 遇到依赖模块兼容错误，使用独立打包 Worker 执行该验证。
- 隔离 Worker 的正式 runChat 与真实模型共六个场景：歌曲、Kevin MacLeod 按音乐人选曲、显式命令均搜索并提交；天气、计数、普通音乐问答均无技能读取或音乐搜索。自然音乐请求的轨迹先 read 再 search_music，公开历史不含技能正文。
- 一次周杰伦按歌手选曲由于平台没有可用直链未生成作品，模型正确说明失败；该轮没有计为成功生成验收。
- 歌曲和音乐人两份真实生成产物均通过 iPhone Air 的原生 Widget 渲染及实际 AVPlayer 播放／暂停测试，测试作品随用例清理。锁屏等待不计入测试通过结果。

证据保存在本地 `.playwright-mcp/native-skills/`。类型检查、SDK 一致性、文档、Notes 与 diff 检查通过。此处的 Workers 测试为本地 Wrangler/workerd；Cloudflare 云端出口对各音乐平台的可用性仍需线上验证，不能由本机结果推断。
