# Agent Note: Shared Widget 中英文内容与缩略图

Status: implemented
Archived: 2026-11-05

## 问题

广场原先每份投稿只有一套名称、简介、源码和截图。请求虽然已有 `language=en|zh-Hans`，原先只影响系统错误文案，不能让用户浏览或采用对应语言的 Widget。纯图形、已经支持两种语言的源码和单语言源码需要区别处理，不能把所有字符串都当作界面文案翻译。

本记录对应 Beads `webclip_widget-41a`。用户已确认首版支持英文和简体中文，名称、简介和源码中的界面文案一起翻译，翻译与各语言缩略图齐全后直接进入待审核；发布后的源码和缩略图由客户端通过无鉴权的 R2 公开 URL 下载，以减少业务 Worker 的下载流量。本地实现与设备验收已完成；已有有效分类的历史已批准投稿保留原批准结果，双语产物补齐后直接发布；缺少分类时进入待审核。

`webclip_widget-41a.18` 补充逐 Widget 人工生产需求。空临时 storage 直接运行会把“请先配置”画面当作有效 PNG；人工生产提供脚本配置界面、语言参考和提交前确认。用户已确认该方案，代码、模拟器及连接本地 server 的真机人工流程验证完成。

## 决策

双语生产、客户端读取及本地和真机验收已完成。生产迁移、Cloudflare R2 部署及同源公开资源由[Keychain 客户端身份](../../implemented/feature/2026-10-26-client-keychain-identity.md)拥有；外部 CDN 未启用，下面的缓存约束仍适用。

### 投稿身份与语言副本

保留一个 shared widget ID，以及原始上传内容和 request_hash。翻译生成派生副本，不改写作者的本地 Widget，也不改变提交重试身份。请求 language 是阅读偏好，不能作为源码语言的判定依据。

`shared_widgets.status` 统一表达投稿生命周期：新增 `pending_translation`、`pending_thumbnail`，沿用 `pending` 表示待审核，以及 `approved`、`rejected`、`deleted`。翻译和所需缩略图全部完成后直接进入 `pending`，不增加 `processing_status` 或 `ready`。全局递增 update_at 继续用于同步。新增按 `(shared_widget_id, language)` 唯一的语言表，保存名称、简介、源码及缩略图引用、哈希、字节数和完成状态；不新增发布身份或另一套公共同步游标。

原始 R2 路径保持不变，派生对象保存在该投稿目录的语言／版本子路径，已完成对象不可原地覆盖。语言副本可以引用同一份原始对象，纯图形不必为每种语言复制源码与图片。版本绑定源内容摘要，后续重试不能把旧源码的截图接到新源码上。

现有 GALLERY_ASSETS 保持私有，拥有原始投稿、待审译文及缩略图。新增公开发布桶，只保存已经批准的产物副本。语言表区分私有产物 key 与公开产物 key；域名由部署配置拥有，DB 不保存与环境绑定的完整 URL。业务 API 按所选语言的公开 key 生成 codeURL 和 thumbnailURL。公开桶配置不暴露私有桶中的任意路径。

### 生产与审核顺序

正常路径为：分享成功 → `pending_translation`（等待翻译）→ `pending_thumbnail`（等待缺失语言缩略图）→ `pending`（待人工审核）→ `approved` 或 `rejected`。分享成功即进入 `pending_translation`；完成翻译后若无须补图，直接进入 `pending`。最后一份所需缩略图提交成功时，原子转为 `pending`。新投稿只有 `pending`、分类有效且两种语言的内容和缩略图完整，批准操作才能成功。已有有效分类的历史已批准投稿保存原审核结果和时间，双语产物补齐时原子恢复 `approved` 并自动尝试发布；发布失败保留批准结果，可重试。`deleted` 仍可从任意非删除状态进入，且不可恢复。

翻译或渲染失败保留当前待处理阶段及有界错误信息，不自动批准，不无限重试。每次生产任务使用可过期的领取凭证，提交结果时核对凭证、输入摘要及投稿未删除；进程退出后可以重新领取。已完成的相同结果重试幂等，不同结果冲突。R2 先写入并校验，D1 再条件提交引用及状态；失败留下的对象按未引用产物规则清理。

Admin 能看到处理阶段和失败原因，并查看两种语言的源码及截图。保留待审核时修正名称和简介的能力，明确按语言编辑；修正只影响所选语言的展示文案，不重算原始 request_hash。批准核对两种语言完整性，审核结果与所有文案修改原子提交。拒绝或删除可终止未完成的生产任务，迟到结果不得恢复处理或发布。

审核批准先持久化 approved，再复制产物到公开桶，绝不在批准决定写入前公开对象。所有目标语言的文件复制并校验完成后，在同一条件事务提交公开 key 并推进父记录 update_at，目录才提供完整条目。部分复制失败返回已批准但发布待重试的结果，保留 approved，不新增生命周期状态；以公开 key 是否齐全判断发布是否完成。重复批准可重试发布，已有同字节对象可复用。公开复制不具有跨 D1/R2 原子性，复制期间已获 URL 的人可能读取部分已批准文件，目录不展示半成品。删除后的发布事务必须失败，迟到复制的对象由发布后的状态复查和定时清理移除，不能重新出现在目录中。

### LLM 翻译脚本

独立批处理脚本复用现有模型 provider 配置和 gallery 导入导出的 Wrangler D1/R2 连接：用户已确认 `npm run trans` 默认直接操作本地存储，`--prod` 显式选择生产绑定，无须启动 server 或传 URL。保留显式 `--url` 连接管理 API，提供只分析、限定投稿、限定批量、存储路径和重试失败任务的入口。命令由[开发指南](../../../../docs/development.md#双语翻译批处理)维护。分享 HTTP 请求不等待模型。

用户已明确要求重写为一次模型请求：发送完整源码、名称（title/name）和简介（desc/summary），返回 en、zh-Hans 两份完整源码及对应元数据。模型负责翻译显示文案、语言变量、数组、对象标签、辅助函数和动态日期文案；不再提取候选位置，也不以间接视图、fetch、宿主调用或动态表达式作为静态阻断条件。输入代码与注释是待翻译数据，模型不获得执行代码或调用工具的权限，也不获得管理凭据。

Prompt 要求保留功能、布局、SDK 调用、网络及存储身份，按目标语言处理显示文案；纯图形或已支持目标语言的源码可保持原字节。模型返回完整双语结果或具体无法处理的原因。脚本校验 JSON、语言唯一性、名称与简介长度、JS 语法、现有 Widget SDK 契约和大小上限，不声称这些检查证明行为或翻译质量。原图复用条件见下方原语言截图复用规则；其余目标进入各语言截图生产。

失败报告区分模型请求、输出截断、JSON 解析和结果校验，保留具体校验原因与语言，不记录请求凭据、原始 provider 响应或完整源码。待人工处理的摘要按完整原因截断，避免 Admin 出现半句话。重试使用既有 --retry-failed；生产租约、原稿身份、历史批准来源和后续发布规则不变。

CLI 在 stderr 实时报告配置加载、连接存储／管理 API、模型初始化、查询队列、领取、翻译和提交阶段，日志携带当前 Widget 名称、ID 与批次序号，显示原稿 widget.js 读取完成的字节数和 SHA-256、模型请求及响应、每种语言的代码校验与产物摘要、保存及失败释放阶段，每个条目完成立即报告状态；等待超过 15 秒时定期打印阶段与已等待秒数。stdout 保留单份最终 JSON，进度不包含完整源码和凭据；读取源码不额外写入本地文件。直接本地模式提示 server 占用存储时改用显式 URL，不自动探测或切换目标。

### 原语言截图复用修复

Admin 等待缩略图列表中的中文译文可以直接沿用原稿源码和文案，但单语言结果未设置 reuseOriginalThumbnail 时，语言记录仍没有 image_key。修复由生产阶段登记对应语言的图片引用，Admin 继续只显示所选版本的截图。

修复前本地服务有 6 个 pending_thumbnail 投稿：轻盈步数、微软股票、农历日历、彩色天气、晴雨之间的中文源码与原稿 SHA-256 相同，中文缩略图缺失；一周步数的中文源码不同，具体变化为数字格式 en-US → zh-CN 和错误文案 Invalid steps → 步数无效。轻盈步数的英文缩略图已经存在，且 legacyReviewStatus 为 approved，补齐中文后沿用历史批准自动发布。

用户已确认并实施的复用条件为：模型分类 single_language，且两份目标源码中恰好一份与原稿字节完全相同，仅该语言设置 reuseOriginalThumbnail。no_language 仍要求两份源码原字节保留并复用；bilingual、mixed、uncertain、两份都相同但不是 no_language，以及代码发生变化的目标继续生成截图。沿用已有模型输出和“已正确的目标源码保持不变”约束，不根据标题或简介中的汉字推断渲染语言，不新增模型字段。

服务端已有的翻译提交会验证原图 PNG、哈希与字节数，并将 R2 原图登记为对应语言的私有图片引用；Admin 读取该语言的 thumbnailURL 后即可显示。语言副本共用同一原始对象即可，不要求额外复制同字节 PNG；批准后的公开语言路径仍由既有发布流程生成。新增翻译按上述条件自动登记，另一语言继续独立补图。

对现有 5 个源码完全相同的中文版本，已通过现有缩略图领取和上传接口补齐：显式指定 zh-Hans，核对当前目标源码与原稿摘要相同，校验并上传原始 PNG。目标语言的生产版本路径保存 R2 图片，沿用当前租约、幂等、状态推进和删除竞态校验；不覆盖已存在图片或其他操作员的有效租约。修复前记录和原图校验摘要、修复后状态与浏览器截图保存在本机 `.playwright-mcp/original-thumbnail-fix/`。五份中文 PNG 下载后均与原图字节一致，中文任务不可再次领取。轻盈步数恢复 approved；微软股票、农历日历、彩色天气、晴雨之间保持 pending_thumbnail，英文产物不变。Admin 五份中文详情均显示对应截图；一周步数的后续人工补齐见下段。

一周步数保留当前中文源码，通过人工核对后补齐原图：源码仅将整数格式 locale 从 en-US 改为 zh-CN，并翻译被捕获且不展示的错误消息。现有截图中的整数在两种 locale 下显示相同；使用现有 Minis SDK 比较有数据、缓存错误、无数据等状态和四种尺寸，共 20 份视图树一致。该投稿的中文图片通过当前生产版本的领取／上传接口保存，源码摘要不变；这是对一份已检查产物的人工补齐，不放宽自动复用的字节一致条件。未采用恢复原稿源码的方案，因为它会撤销已有本地化，并涉及源码身份、版本及租约的替换。

验证覆盖中文／英文单语言的唯一原字节目标、无语言内容、双语／混合、两份同字节的歧义结果、改动过的代码、损坏原图、已有图片和被占用的租约；真实本地接口确认原语言 PNG 可读、另一语言仍缺图及历史批准恢复；隔离存储测试验证普通投稿补齐后进入待审核，Gallery 测试验证重复补齐和删除后的迟到提交不会复活状态。

### 无配置表单的缩略图生产

真实模型生成的静态 Widget 只有 widget()、没有 render()，原生分享和英文原图复用成功；中文生产点击生成预览后不能提交。首次失败证据保存在 `.playwright-mcp/gallery-native-siLAZM/`。XCTest 的元素快照确认提交按钮可见但 disabled，并非滚动导致控件不可见。

`MiniAppRuntime.start()` 对无 render 的脚本返回空应用视图，明确不启动应用生命周期。修复前的 `ThumbnailProductionSession.preview()` 无条件调用只支持运行中应用的 projectWidget，SDK 因未启动应用抛出 The app is not running。配置型生产测试有 render，因此没有覆盖这个分支。

缩略图会话沿用 RunnerWidgetPreview 的入口选择规则：有配置表单时投影当前运行实例；只有 widget 时使用 WidgetRunner 执行其 initialState／onAppear／widget。继续使用该语言的生产 storage、网络、宿主语言和 PNG 校验，保留显式预览／提交、取消与租约约束。本次渲染来源的初始化及缓存写入不当作外部配置变更；配置表单仍要求预览期间状态和其他来源的 storage 版本不变。单元回归覆盖静态 widget-only、带初始化 storage 的 widget-only、英文／中文 PNG 与失败不上传，真实原生流程验证其分享和补图入口。

不改变 MiniAppRuntime.start 的共享生命周期契约，也不为模型产物伪造 render 或要求模型增加无用配置页；这两种做法会扩大影响范围或掩盖合法源码无法补图的问题。用户已确认修复并继续完整验收。

### 天气补图的缓存写入与失败原因

`webclip_widget-41a.22` 诊断用户在「彩色天气」英文补图中看到的 2 MiB PNG 错误。故障版本的 `ThumbnailProductionSession` 把每次 storage 写入都计入配置版本；该投稿在 widget() 成功取数后写入 `pastel.weather.cache.v1`，因此投影完成后版本必然不同，PNG 编码尚未开始就抛出 invalidImage。同一个错误还用于未就绪、运行问题、资源无效及真正的 PNG 超限，界面无法区分这些原因。

已用本地管理 API 只读取得当前英文源码，并在实际 SDK prelude 中执行未配置／已配置城市两个分支。已配置分支返回视图且没有 JavaScript 错误，只发生天气请求及一次缓存写入；按故障版本的生产会话规则计算，storage 版本从 0 变为 2，足以触发拒绝。未配置分支没有该写入。证据在本机 `.playwright-mcp/weather-diagnosis-IV7Pqz/`；这是 SDK 与会话条件的隔离复现；原生 PNG 和真机服务验收见下方验证记录，日常投稿未修改。

用户已确认本项与下方真实数据接入一并修复。生产会话复用[预览缓存写入的来源标识](../../implemented/bug-fix/2026-10-22-widgee-preview-storage-feedback.md)，将标识传给 projectWidget／WidgetRunner。ProductionStorage 继续记录所有在途写入，但仅非本次预览来源的写入增加配置版本；缓存必须实际保存完成后才可确认 PNG。用户交互、宿主状态变化、其他来源写入、取消或租约失效仍使旧预览不可提交。既有运行页与共享运行时契约保持有效，该笔记仍独立拥有异步来源传播的理由与限制。

失败提示按原因区分：会话未就绪、配置变化、运行问题、图片无法解码或解析、PNG 编码失败和实际字节超限。2 MiB 提示仅用于已编码 PNG 的字节数超过上限；大小限制、上传身份与显式提交流程继续保留。

原生回归覆盖：使用实际「彩色天气」投影路径和可控天气返回，验证缓存落盘、生成可解码 PNG、预览与上传字节一致；通过屏障在投影等待期间保存配置，证明结果失效且不上传；覆盖不同错误原因与真实超限分支。重跑相关人工生产测试，并构建安装真机供用户重试。测试使用独立存储与服务数据，不能领取或覆盖用户当前投稿来制造通过。

缓存来源修复与设备数据接入分开验证。下方方案明确真实数据能力；隔离的缓存回归不能代替真机 WeatherKit 与健康权限验收。

在设置中的实验功能入口添加独立 View，入口受 `WIDGEE_EXPERIMENTAL_FEATURES` 控制。页面拉取等待缩略图的任务，显示目标语言、执行进度、预览和失败原因，支持运行待处理批次、停止及重试。生产以前台串行人工步骤执行，不依赖 iOS 后台常驻。

[Admin 多设备登录](../../implemented/feature/2026-10-23-admin-session-login.md)调整浏览器登录，保留 iOS 与翻译脚本 API 模式的管理口令调用兼容性。

生产接口使用管理鉴权，复用 ADMIN_TOKEN 的授权边界；操作员在实验页面输入管理员令牌，App 按服务器将其保存到本机 Keychain。编译开关不构成服务器权限检查，客户端 UUID 不能读取未审核任务或写入缩略图。

用户已确认管理员令牌自动保存方案，对应 `webclip_widget-41a.17`：填写后自动保存，重新进入页面和重启 App 后自动恢复。生产页面使用独立 Keychain 项，按服务 origin（协议、主机、有效端口）隔离，使用 `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`，不参与 iCloud 同步、不复用聊天服务令牌或 Widget 脚本凭据。输入变更即更新当前服务的已保存值，清空输入即删除该服务的令牌；不要求先开始生产。离开页面继续取消生产并清除内存引用，但保留 Keychain；再次进入恢复当前服务的令牌。切换服务先停止任务，再加载新服务对应值，不把旧令牌复制到新地址。Keychain 读取、保存或删除失败在页面明确显示，不静默宣称保存成功。页面文案与运行说明同步保存和删除语义；生产测试结束时清空独立测试服务的管理令牌。

每个任务包含语言、源码摘要、SDK、推荐 size 和领取凭证。客户端下载并校验对应源码，以临时 app ID、独立临时 storage 运行，然后复用 WidgetThumbnailStore 的 PNG 输出。显式选择目标语言的宿主资源；对依赖设备语言的源码，还需让生产用桥接返回目标语言，不能只设置 SwiftUI locale。

生产复用普通运行的真实模块及系统权限，脚本存储使用独立临时命名空间。真实图片在资源释放前转换为内联 PNG；生命周期、资源解析及渲染失败不能作为成功空图上传。依赖作者私有配置的作品需要人工处理，不能承诺重现作者设备截图。

截图以统一浅色、标准字号和投稿 size 生成，PNG 不超过现有 2 MiB 上限。仅在确认目标语言画面相同、没有宿主语言影响时复用原图；需要重新生成时可为原语言和译文都建立缩略图任务。上传绑定语言、源码摘要、生产版本和领取凭证，服务端验证 PNG 与任务有效性。取消或完成后清理临时数据与网络资源，不自动采用到资料库。

#### 逐 Widget 配置、预览与提交

点击“运行待处理批次”后只准备当前 Widget，暂停在人工处理页面。页面明确区分“本次提交语言”和“参考版本”：参考版本可选择原稿、简体中文或 English，展示对应标题、简介、已有截图及可展开的只读源码；缺少截图明确标记。切换参考版本不改变上传目标，也不把参考图当作待提交图片。

当前目标语言运行源码自身的配置界面，复用 MiniAppHost／MiniAppView 的输入、选择和保存交互，变量由脚本写入本次独立 storage。宿主不通过字符串替换改写源码，不自动推断任意 JavaScript 局部变量；没有配置界面的作品可直接预览，需要配置但未提供入口的作品显示运行结果，允许操作员记录原因并跳过。配置区和 Widget 画面分别展示，不能把输入表单截成缩略图。

点击“生成预览”时，有 render() 的脚本从当前运行实例投影 widget()；无 render() 的脚本通过 WidgetRunner 在本语言临时 storage 和普通 Widget 桥接中完成初始化并运行 widget()。随后解析本地及网络图片并生成最终 PNG，展示这份待上传图片。两类脚本都允许本次预览来源的初始化和缓存写入，待其落盘后记录预览版本；投影期间状态变化或其他来源的 storage 写入使结果失效。只有预览成功且配置、运行状态和源码版本未变化时，才启用“提交并继续”。预览后的任何输入、配置写入或状态变化使确认结果失效，必须重新预览；提交上传用户看到的相同 PNG，不临时重跑网络或重新截图。PNG 校验无法判断脚本是否展示了业务错误或缺少配置，画面是否可用由操作员确认。

一次提交只完成当前语言，成功后优先领取同一 Widget 的下一个缺图语言；该 Widget 可领取的语言完成后再进入下一个 Widget。各语言使用独立临时目录；提供显式“复制上一语言配置”以减少重复输入，复制后仍需运行、核对和预览，不自动共享正在写入的缓存或语言文案。跨 Widget 不复制配置。配置仅用于生产，不附加到投稿、源码或公开资源；任务结束清理临时目录。输入的值可能被脚本发给其网络服务，也可能出现在最终截图中。

配置复制包含本次临时 storage、文件、图片引用及脚本 Keychain，下一语言持有独立副本；不自动引入已采用 Widget 的配置和凭据。系统 API 的真实读写及权限遵循普通运行语义，存储隔离不提供系统操作回滚。

人工处理期间以前台心跳续期现有 15 分钟租约。新增管理端续期和释放操作，绑定 Widget、语言、领取凭证、源码摘要及生产版本；仅未过期、未删除且仍缺图的当前持有者可续期或释放，不能复活旧领取。失去租约立即禁用提交，重新领取并核对版本后才能重新预览。离页、停止或进入后台取消工作并尽力释放；网络不可达时由租约到期回收。普通停止不记作生产失败。

“跳过并记录原因”释放当前任务并保留失败原因，普通批次后续不自动重复领取；当前批次排除已跳过的 Widget，避免在“重试失败任务”模式内循环。上传失败时保留仍有效的预览并允许重试；已提交成功的语言不回滚，不重复配置。全部任务结束、取消和语言切换均清理对应运行实例与网络资源。

已确认的取舍是：每种缺图语言分别预览并提交、配置按语言隔离且允许显式复制，以及通过续期支持长时间人工编辑。历史批准自动发布要求有效分类；无需补图的原图复用和管理员令牌保存规则继续有效。

### 按语言读取与缓存

业务 API 沿用 URL 查询参数 `language=en|zh-Hans`，省略或未知值回退英文。列表、详情和生产接口保留各自的鉴权规则；列表与详情按语言返回名称、简介、完整的 codeURL／thumbnailURL、SDK、文件哈希及字节数，不悄悄退回另一种语言。

客户端直接 GET 返回的资源 URL，默认使用同一 Worker 的 HTTPS 公开资源入口，可选配置独立 CDN；传输选择由[Keychain 客户端身份](../../implemented/feature/2026-10-26-client-keychain-identity.md)拥有。两种环境均不附带 App token、ADMIN_TOKEN 或用户身份，不使用需要签名或短时续期的链接。资源语言和版本由对象路径确定，R2 不解析 language 查询参数。纯图形的多个语言记录可以返回同一公开 URL。示例地址为 `https://assets.example.com/shared-widgets/<id>/zh-Hans/<version>/widget.js` 与同目录的 `thumbnail.png`；实际生产域名由部署配置决定。

codeURL 返回原始 UTF-8 JavaScript 文件，不再返回包含 code 的 JSON 包装；thumbnailURL 返回 PNG。GalleryItem 保存服务端返回的 URL，下载器使用这些 URL，而不是按 ID 拼接 Worker 路径。客户端仍以目录摘要校验字节数、SHA-256、SDK 和 Widget 契约后采用，下载失败或不匹配时不得保存半成品。已发布资产的旧业务代理读取入口随客户端协调升级移除；未审核源码与截图继续通过管理接口读取，实验客户端拉任务与上传仍需鉴权。

独立 CDN 模式使用绑定到 R2 的专用自定义域名，避免业务 Worker 处理资产请求。[Cloudflare R2 public buckets 文档](https://developers.cloudflare.com/r2/buckets/public-buckets/)明确 r2.dev 用于非生产场景，生产缓存使用自定义域名。源码和 PNG 的缓存契约为 `Cache-Control: public, max-age=300, s-maxage=300, must-revalidate`，CDN 规则不额外延长 TTL 或启用过期内容回源失败复用。不可变版本路径避免新产物覆盖旧缓存；首版不采用一年期 immutable 缓存，以保留有限的删除撤回窗口。

所有影响公开内容的语言副本提交、公开引用提交与审核／删除都在同一 D1 事务内推进父记录的 update_at。公共列表继续按父记录分页后投影语言，不先过滤尚无译文的行；不可见记录返回最小状态标记，让客户端能移除缓存且持续推进游标。数据库 approved 但公开引用尚不齐全的条目，对普通客户端返回不带内容的 pending 标记；Admin 仍看到真实审核状态和发布缺失信息。公开引用齐全后推进游标并返回完整 approved 摘要，不能返回缺少字段的 approved 内容。

缓存记录增加所用语言。App 启动及回到前台时比较当前 AppLanguage，变化时取消旧语言请求、清空广场目录／游标／图片和内存详情，从 update_at=0 重建。旧缓存没有语言字段时也重建。请求捕获语言与本轮加载标识，写盘和更新内存前再次校验，取消失败或迟到响应也不能污染新缓存。清理失败不得加载旧语言目录冒充新语言数据。

不把 language 拼进 GalleryAPI.scope，因为这个值也拥有已采用 Widget 的来源身份。已采用 Widget 保持独立本地副本和原语言，切换语言不覆盖本地编辑，也不因同一投稿不同语言而自动重复采用。未完成分享的持久化副本是重试数据，不属于需要清空的浏览缓存。

### npm run dev 本地验证

根目录 `npm run dev` 当前转发到 backend 的 `wrangler dev`，D1 和 R2 使用 Wrangler 本地持久化。新增的公开发布桶也使用本地 R2 绑定，私有到公开的复制、语言选择与哈希校验走同一实现，不依赖真实 Cloudflare 桶或域名。

本地 R2 绑定不自动提供生产自定义域名的公开下载入口。dev 显式启用 `/public-assets/<object-key>` 路由，生产默认同样使用此只读入口，直接读取本地公开发布桶，仅允许 GET／HEAD，无需 token，不查 D1 审核状态，也不能访问私有桶或写入对象。路由校验对象路径并返回与生产相同的原始 JS／PNG、内容类型及缓存头。该路由复用同一个本地 server 和端口，无须额外启动资源服务器。

本地列表按当前请求的 origin 构造绝对资源 URL，例如 `http://127.0.0.1:8787/public-assets/shared-widgets/<id>/zh-Hans/<version>/widget.js`。真机连接时使用 Mac 的局域网地址，列表返回同一个可达地址，不能写死 localhost 或 127.0.0.1；真机开发服务继续按现有方式监听 `0.0.0.0`。iOS 资源下载沿用本地开发所需的 HTTP 支持，不在生产链接中放宽 HTTPS 要求，也不复用会附加 API 凭据的请求构造器。

生产部署不启用本地资源路由，缺少公开域名配置时报配置错误，不能静默退回 Worker 代理；开发模式由启动配置决定，不根据客户端伪造的 Host 或查询参数开启。客户端在两种环境下都直接使用列表返回的 URL，无须自己判断 R2 路径或拼接本地地址。

本地验收覆盖分享、翻译、补图、批准复制、匿名下载、切语言、采用及删除。这里的资产字节由本地 Worker 模拟公开 R2 返回，不能用本地请求证明生产绕过 Worker 或 CDN 实际缓存／撤回时效；这些项目仍需要真实 R2 自定义域名验证。

### 历史数据、备份与兼容

新增 migration，不修改已应用的迁移。历史原始产物、投稿 ID 与提交摘要均保留。在一次协调升级中暂停广场公开入口，完成历史 pending／approved 内容的翻译和补图后恢复，避免静默把原语言当成英文。历史 pending 内容产物齐全后仍待人工审核；具有有效分类的历史 approved 内容沿用原批准决定；没有分类时需人工分类与审核。历史 rejected 保留审核结果，不自动重新发布；deleted 不再处理。迁移用只读的 `legacy_review_status` 保存历史 approved 的批准来源，保留 `reviewed_at`，将其当前状态改为 `pending_translation` 并推进游标。双语产物补齐且分类有效后恢复 `approved` 并自动发布，没有分类则进入 `pending`。分类必填、旧备份重审和本地数据整理见[分类审核](2026-10-25-shared-widget-categories.md)。迁移窗口、历史数量和实际生产部署需单独执行与验证。

更新 gallery-data 导入导出格式以包含语言记录、生命周期及所有被引用产物，继续读取旧备份；旧备份导入后补齐语言生产信息。公开副本可从备份中的已批准产物重建，按目标环境域名返回 URL；不得把待审产物恢复到公开桶。重复导入保留目标已有状态与版本，不能覆盖译文或复活 deleted。处理中任务的临时领取凭证不作为可恢复的有效租约。导出／导入期间的写入协调范围包括翻译、缩略图和发布复制任务。

删除先保留 deleted 元数据和同步标记，再清理私有与公开桶中的全部语言产物，不能只删除原始两个文件。R2 清理失败继续重试；CDN purge 可加快撤回，但不能承诺所有缓存即时失效。清理完成且迟到复制收敛后，遵守上述配置的在线缓存最多继续使用剩余 5 分钟 TTL；清理失败或任务尚未收敛时不承诺该上限。第三方已下载文件和已采用本地副本无法撤回。D1 标记 deleted 本身不能阻止旧公开 URL 读取。

## 曾考虑的替代方案

**继续使用样例步数，仅修改成功提示。** 可以诚实表达示例，但不满足人工补图页面读取当前步数与指定城市天气的预期。真实数据需要系统能力与授权，不能通过翻译或缓存修复获得。

**生产会话直接使用完整真实模块注册表。** 会同时开放健康写入、私人文件及其他无关能力；采用步数、天气和必要地理查询的窄范围接入。

**提高 PNG 上限或降低截图分辨率。** 彩色天气的可复现拒绝发生在 PNG 编码之前，修改图片参数无法修正缓存版本冲突。

**生成期间忽略所有 storage 写入。** 会漏掉异步天气等待期间的配置保存；按调用来源区分才能同时允许自身缓存和拒绝过期截图。

**只扩展 HTTP 测试。** 能覆盖状态与图片身份，但无法证明 iOS 分享上传、原生 PNG 生成和采用副本正确，因此同时保留完整原生验收。

**所有回归都实时调用模型。** 模型输出变化会混淆生产状态回归与翻译质量问题；受控场景固定外部响应，另以真实模型原生流程验证实际集成。

**Admin 缺图时直接回退到原始投稿截图。** 可以马上出现图片，但不会补齐对应语言的 R2/D1 生产记录，另一语言还可能显示错误截图。采用生产阶段登记原图和存量任务补齐。

**仅凭原稿标题是中文就复用中文截图。** 元数据语言不证明源码实际显示语言；已有一周步数的中文版本还包含代码变化。采用单语言分类和唯一原字节目标约束，代码变化项保留补拍流程。

**自动渲染后只增加一个确认按钮。** 可以阻止自动上传，但空 storage 和不可交互的渲染器仍无法填写变量，不能解决需要配置的 Widget。

**生产时直接打开个人资料库的运行页面。** 能复用配置交互，但会引入资料库落盘和已有个人配置。生产页面复用运行宿主与控件，单独拥有临时存储；原先同时限制设备能力的取舍由[真实运行决策](../../implemented/bug-fix/2026-10-24-thumbnail-real-runtime.md)替代。

**中英文始终共享同一份可写配置目录。** 少填一次变量，但一种语言的缓存、初始化或保存会影响另一种语言，导致已确认预览失效。按语言隔离并显式复制，仍要求逐语言确认。

**所有翻译操作必须通过运行中的管理 API。** 这要求本地启动 server、配置管理口令，线上另传地址。默认复用导入导出的 D1/R2 连接，直接调用同一 GalleryStore 的领取、校验和提交逻辑；显式 URL 模式保留给需要经管理 API 访问的环境。

**原语言先审核发布，再补译文。** 可以缩短发布等待，但不同语言用户会看到不同完整度。用户已选择双语源码和缩略图齐全后审核发布。

**每种语言另建独立 shared widget。** 读接口改动较少，但拆散投稿身份、审核、删除和本地采用去重。使用一个投稿下的语言副本。

**在单份源码中注入完整运行时国际化框架。** 方便运行时切换，但要求改写用户源码结构、影响本地执行和 SDK 约定。当前需求可以由独立语言副本完成；已有可靠双语代码仍允许复用。

**预先抽取显示字符串并禁止候选之外的 AST 变化。** 真实本地 6 份待翻译投稿全部记录失败；3 份明确被动态文案／间接视图限制阻断，3 份异常被通用错误掩盖。该方案无法处理常见的月份数组、显示变量、辅助函数和动态文案。用户选择直接让模型翻译完整源码，功能保留由 prompt、源码检查与客户端验收共同约束，不再承诺 AST 不变。

**独立 processing_status 保存翻译进度，并以 ready 表示产物齐全。** 正常投稿的翻译、补图和审核按顺序发生，产物齐全就意味着待审核；两套状态会重复表达这一条件。统一使用 status，完成补图后直接进入 pending。历史已批准内容回填时保存批准来源，产物补齐后恢复批准状态。

**服务端或浏览器生成截图。** 当前 Widget 使用原生 SwiftUI 渲染，复用 iOS 能保持实际外观；代价是生产队列依赖在线且前台运行的实验客户端。

**已发布资源继续经 Worker 鉴权代理，或改用短时签名 URL。** 前者保留每次下载检查删除状态的能力，但仍占用业务 Worker；后者引入续期且不满足无需鉴权的公开链接要求。已批准资源使用 R2 公开域名直出，接受删除需清理对象并等待缓存失效的代价。

**直接公开现有 GALLERY_ASSETS 桶。** 会让待审核、拒绝及处理中产物也可通过对象 URL 读取，列表过滤无法保护这些文件。保留私有桶，批准后复制到公开桶。

**生产令牌继续只保留在内存。** 每次打开页面都需要重填，不满足本次自动保存要求。

**生产令牌保存到 UserDefaults。** 接入更少，但已有服务令牌使用 Keychain；管理员令牌采用独立 Keychain 项，保持与其他凭据隔离并支持系统数据保护。

## 回归覆盖与部署要求

- 人工生产使用必须配置后才能显示内容的 Widget：点击批次后不会上传，输入并保存变量后可看到正确目标语言 PNG；输入或运行状态变化后旧预览不能提交。提交的字节与展示的 PNG 一致，双击不重复上传，上传成功才继续下一语言或下一 Widget。
- 原稿与中英文标题、简介、截图和源码可切换查看，缺图明确显示；查看参考版本不改变目标任务。两语言可分别配置，显式复制后值可恢复，且另一语言和其他 Widget 的存储不被改写。退出后临时资源清理，个人资料库与凭据不变。
- 续期、释放、跳过和失败重试覆盖真实 API；过期、错误凭证、错误摘要／版本、删除及迟到响应均拒绝写入。人工停留超过原始租约时仍可通过续期完成；丢失租约禁止提交；重试失败批次不会反复领取本次已跳过项。
- 在模拟器及连接本地 server 的真机上完成配置型 Widget 的原稿参照、双语设置、生成预览、人工提交和批次继续，保留设备截图；运行对应 Swift、服务端、文档与本地化检查。人工流程使用独立配置型样例验收，不以既有自动批次测试替代。

- 中文、英文、纯图形、已有双语、混合文案及难以静态判断的源码均有样例；纯图形源码不改字节，名称和简介可以独立翻译，复杂未处理项不得进入待审核。
- 全量源码与名称、简介进入模型请求；数组、显示变量、helper、动态日期和网络数字数据不会因写法被静态拒绝。JSON 无效、语言缺失／重复、JS 语法错误、非法 SDK、超限源码与元数据通过实际入口被拒绝；未授权读写、错误源码版本和无效 PNG 仍有反例。真实失败投稿必须纳入模型验证，不以简单字符串样例代替。
- 新投稿从 pending_translation 开始，缺图时进入 pending_thumbnail，所需产物齐全后直接进入 pending；只在人工批准后公开。翻译、补图失败可重试。并发领取、任务过期、部分 R2 写入、删除后迟到上传及重复结果不会拼接错误产物或复活投稿。
- 两种 language 的列表、详情、代码、图片一致；单语言变更推进父游标，分页没有遗漏，删除同步两种语言。切换语言后从 0 重建，旧请求不能写回，已采用和待重试分享副本保留。
- 生产列表返回目标语言的公开 HTTPS URL；不带任何 token 也能下载已发布源码和 PNG，默认生产资源由同一 Worker 读取公开桶。客户端读取原始 JS 并校验摘要；未审核产物不在公开桶中。批准后复制失败可重试，目录不暴露半成品，删除与迟到复制最终清理两个桶。验证实际域名、缓存头、CDN TTL 与删除后的缓存失效；本地替身测试不能替代真实 R2/CDN 验收。
- `npm run dev` 单服务支持本地公开资产下载，无须云端资源或第二个服务；匿名 GET／HEAD 可读取已发布文件，不能写入或读取私有待审文件。真机收到的资源 URL 使用 Mac 可达地址；默认生产配置也启用只读公开资源入口；配置 CDN 时关闭该入口。实际运行本地完整流程，不能只验证构造出的 URL 字符串。
- 实验开关关闭时入口不存在，开启时可在同一设备处理两种语言；真实模型生成和翻译的 Widget 完成提交、双语截图、审核及另一用户采用，检查中英文布局、宿主默认文案与行为，保留真实流程 GIF／设备证据。
- 历史数据迁移、备份往返、旧备份导入、重复导入和全部语言产物删除均验证。更新 Widgee 协议、架构、开发指南、iOS／Admin 使用说明及活跃笔记，运行对应后端、脚本、iOS 和文档门禁。

## 后果

人工生产的配置型 Widget 可能依赖未提供的作者文件或私人权限，不能仅靠配置输入恢复。运行期状态持续变化的脚本可能反复使预览失效，需要明确显示原因；宿主不能证明脚本内部的草稿已经保存。心跳和释放增加管理 API，但不改变公开下载协议或已有产物身份。本次不增加源码编辑、通用变量提取或跨 App 重启的生产草稿恢复；独立临时目录与语言记录允许后续另行扩展。

自动保存会让管理凭据在页面退出后继续留在本机，删除方式是清空输入。按 origin 隔离意味着局域网 IP 或端口改变时要为新地址重新填写；该约束避免将管理员令牌自动发送到不同服务。

完整源码翻译可能漏译、误译或改变行为，尤其是显示值同时作为逻辑键、外部数据和复杂语言分支。基本语法及 SDK 校验不能证明功能等价；prompt 要求保留逻辑，实际语言质量与布局依靠源码和客户端验收。具有有效分类的历史已批准内容按原批准结果自动发布；无分类内容需完成分类审核。

重渲染不能恢复未上传的作者 storage 和私有文件，网络数据、日期及地图也可能与原截图不同。原生运行时不是完整的不可信代码安全沙箱；生产客户端复用真实系统能力，临时存储隔离不阻止系统或远端写入。纯图形是否真的不受宿主语言影响，需要按源码与实际渲染判断。

前台 iOS 生产者不在线时会积压，双语齐全再发布会延长等待。首版不建设常驻渲染设备调度、自动翻译外部内容、繁体中文或其他语言，也不更新已采用的本地 Widget；语言表和独立产物引用保留后续扩展空间。

公开资源允许任何获得 URL 的人下载、转发或保存，不能再逐请求按 D1 状态阻止访问。独立公开桶增加产物复制、发布恢复和存储成本，CDN 命中可减少 R2 读取，资产直出减少业务 Worker 的请求和转发。公开域名、桶与缓存规则需要部署配置，本地测试不能证明实际 CDN 撤回时效。

语言表、完整源码翻译及人工处理出口、管理凭据保护的前台渲染页面、公开发布桶与缓存时效均纳入实施范围。具有有效分类的历史已批准内容不重新人工审核，因此自动发布的译文仍存在误译风险。本轮按用户要求不上线，真机只连接 Mac 本地 server。真实 R2/CDN 验收、云端迁移、生产批处理和部署由 Beads `webclip_widget-41a.9` 留待后续；本地结果不证明生产直出或 CDN 撤回时效。
