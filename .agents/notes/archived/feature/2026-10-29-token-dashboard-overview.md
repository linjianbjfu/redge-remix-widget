# Agent Note: Token 看板整体汇总

Status: implemented
Archived: 2026-11-05

## 问题

逐 Session、Turn、Request 的 ID 表格适合追踪单次调用，却难以直接判断全部聊天的用量和性能。用户明确要求将本看板改成所有 Session、Turn 的整体汇总。

## 决策

顶部展示观测 Session/Turn/Request 数、Token 总量和均值；业务轮次独立汇总结束数、状态与完整处理耗时；趋势和模型、工具分组展示整体分布与耗时。Turn 阶段图合并首次模型调用、工具执行、工具结果续推、压缩和其他模型调用的单次调用耗时，以横向条形图比较各阶段；不显示独立的工具平均耗时图。模型处理与输出合并计时，输入与传输未采集，不推算其时长；循环阶段的统计值不能相加为整轮耗时。移除实体 ID 变量、逐条明细、排行与下钻链接。保留日期、模型、请求类型和工具筛选。

计数和均值从完整筛选范围内去重事实计算，不汇总 Top N 行。Session/Turn 用量覆盖数来自模型请求，业务完成数来自 turn 终态；模型筛选不归因整轮处理耗时。全部耗时面板统一使用“耗时口径”变量，默认平均值，可选 P50/P95/P99。平均值与精确分位数直接来自去重的原始调用或轮次耗时，不对均值再次求分位数；零耗时有效，未知和未执行排除。数量和 Token 不受该变量影响。请求类型保留筛选，不显示分组汇总表。无有效样本显示暂无数据。采集和私有身份数据保持现有契约。

整体汇总调整[服务端 Token 分析](2026-10-29-server-token-usage-analytics.md)的看板展示，其采集与可靠性决策继续有效。

## 曾考虑的替代方案

**保留逐实体明细、仅在上方加汇总。** 用户明确不需要逐 Session、Turn 的展示，因此看板直接呈现整体；底层查询和埋点仍支持后续独立诊断工具。

## 验证

真实 WAE 固定样例五个 request、两个 session、三个 turn，已观测 Token 4950；平均每 Session 2475、每 Turn 1650。结束轮次累计处理 16000 毫秒。图表没有实体 ID 列或实体筛选，模板测试拒绝它们；新增汇总从完整范围去重，不设置 Top N。真实 Grafana 展示全部测试用户的 6 个 Session、7 个 Turn、15 个 request 和 66282 Token，趋势及分组正常；数据包含重复投递、未知与冲突样例。固定样例的四种耗时口径分别为平均 900ms、P50 500ms、P95/P99 2000ms；每种口径均执行全部 15 个看板查询目标，计数和 Token 不变，空/未知样本返回空值，真实工具的 0ms 样本保留。Grafana 下拉框、阶段图及模型/轮次/工具表验证四种口径切换。

## 后果

观测用量并非精确账本。日期按事件结束归属；无 request 的失败轮次可计入结束轮次但不计入模型请求覆盖数。Session Token 均值为总已知 Token 除以观测 Session 数，包含部分未知用量会偏低，显式标为已观测。
