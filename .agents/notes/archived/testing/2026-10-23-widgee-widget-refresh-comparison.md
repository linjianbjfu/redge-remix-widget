# Agent Note: Widgee 桌面交互刷新的真机与模拟器对照

Status: implemented
Archived: 2026-11-05

## 问题

普通 iPhone 模拟器中，桌面按钮已写入 storage 和 snapshot，屏幕仍显示旧计数。单凭 reload 日志、静态代码或构建成功不能区分项目缺陷与系统显示调度；可访问性树也可能与实际像素不同。

## 决策

刷新诊断使用固定无网络计数器，分别采集真实桌面点击、共享目录数据、AX 文本与实际截图。宿主测试只承担发布、脚本往返验证与清理；桌面阶段不启动宿主。文件采样器不给设备发送 reload，不把读取失败解释为没有发生写入。XCTest 与 Mac 文件采样分别记录单调时钟区间，不跨时钟相减或把 AX 耗时称为渲染耗时。具体命令、观测值与限制由[诊断文档](../../../../docs/widget-refresh-diagnostics.md)维护。

两端各两次有效点击中，真机截图和数据一致；模拟器的数据与 AX 已更新，截图仍落后一值。模拟器重启后显示已持久化的新值。该证据支持记录本轮模拟器环境的可见更新限制，保留现有 MiniAppActionIntent 的快照保存与 reload 路径。OS 小版本、尺寸和渲染机制尚未被独立控制，不据此指定某个系统组件为根因。

[配置保存刷新](../bug-fix/2026-10-19-widgee-configuration-widget-refresh.md)与[预览缓存来源](../bug-fix/2026-10-22-widgee-preview-storage-feedback.md)继续拥有各自运行时决策，本诊断不取代它们；它们保持活跃。

## 曾考虑的替代方案

**直接增加 reload 调用或缩短时间线间隔。** 当前 intent 已保存有效快照并请求重载；真机与模拟器都读到新数据。缺少因果证据时改变调度会干扰复现，且不能保证屏幕刷新。

**继续使用真实模型生成的不同计数器。** 源码差异使设备对照混入脚本因素。固定源码与两端实际源文件哈希消除此因素；模型生成链路有独立验收。

**只断言 XCTest 文本或 chronod reload 成功。** 实测模拟器 AX 断言通过而同轮截图仍旧；这两类结果不能承担可见刷新验收。

## 验证

真机与专用普通模拟器各通过 fixture 发布、临时目录中的 action 持久化往返、两次桌面 AX 观察与匹配 fixture 清理。桌面 AX 通过与像素观察分别报告；本次并未把模拟器截图判为及时刷新通过。[测量数据](../../../../docs/measurements/widget-refresh-2026-10-23.json)记录源码哈希、读区间、截图与清理核对。

真机原八项资料库及原源码保持一致，连接地址与用户偏好未变，Keychain 未读写。用户恢复原股票组件选择后才清理测试作品。专用模拟器已关闭，未启动 backend。

## 后果

同一个自包含 fixture 可以重复验证数据路径和可见结果，避免自动化误报成功。它只证明记录环境中的行为，不提供秒级 WidgetKit 调度保证。帧级首见时间、跨版本系统归因及真实模型生成保持为独立验证范围；需要这些结论时再扩展测量，不能从当前四次点击外推。
