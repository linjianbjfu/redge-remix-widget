# Agent Note: Widgee 预览缓存写入的刷新来源

Status: implemented
Archived: 2026-11-05

## 问题

“彩色天气组件”的 widget() 在天气请求成功后写入包含 savedAt 的缓存。运行页把同一目录的每次 storage 写入都作为新的预览输入；预览因此丢弃自身结果并反复请求天气，八次后显示“预览期间内容持续变化”。缓存每次含新时间，比较值是否相同不能消除循环。

## 决策

每个运行预览拥有进程内来源标识。JavaScript 入口在运行时串行队列上设置调用来源，原生桥接捕获来源，并在返回 JavaScript 时恢复同一来源；StorageModule 在成功落盘后将其带入 StorageChange。当前预览忽略自身来源的通知，其他来源仍刷新。标识绑定预览实例，通知延迟到渲染完成后送达也不触发自身刷新。

配置宿主的 projectWidget 按调用传递来源；独立 WidgetRunner 的渲染、操作与再次渲染共享该次运行的来源。配置事件从自己的执行入口开始，不能继承正在等待的投影来源。缓存照常保存，资料库与 WidgetKit 照常接收成功写入通知；状态版本保护与八次连续失效上限保持有效。

本修复收窄[配置保存后的刷新](2026-10-19-widgee-configuration-widget-refresh.md)的通知消费条件，保留其共享投影、生命周期、落盘通知及 WidgetKit 调度决策，旧笔记保持活跃。[预览取消与超时](../../proposed/bug-fix/2026-10-22-widgee-preview-cancellation-timeout.md)拥有独立的任务退出缺口，不在本修复中扩大范围。

## 曾考虑的替代方案

**渲染期间忽略所有存储通知。** 会漏掉天气请求等待期间用户保存的配置。

**增加重试次数或消除相同值写入。** 前者延长循环；后者不能处理包含新时间的天气缓存。

**关闭存储自动刷新或修改这份生成源码。** 会丢失仅写 storage 的配置更新，或只修复单份产物，不能覆盖其他正常缓存写入。

## 验证

运行时相关 35 项测试通过，来源专项使用屏障重叠投影与配置保存，覆盖多次 await、Promise.all 和异常后的来源恢复。真机 14 项单元与集成测试覆盖配置投影、纯 Widget 渲染与操作、缓存确实落盘、仅写 storage 的保存、并发保存丢弃旧结果、不同应用或目录过滤，以及真实状态持续变化时的中止保护。

两项负例分别移除异步来源传递和预览来源过滤，均被回归拒绝；后者复现相同的持续变化错误。真机 UI 使用原账号和原天气产物连续两次点击卡片，均显示实时天气并正常关闭，未修改位置配置或发送模型请求。手机原连接设置核对一致，并已无测试覆盖参数正常启动。[测量记录](../../../../docs/measurements/widgee-preview-storage-2026-10-22.json)与[截图](../../../../docs/measurements/widgee-preview-storage-2026-10-22.png)保留证据。

## 后果

生成脚本可在 widget() 中保存天气等缓存，无需改写已有服务端产物或提高重试次数。来源只用于本进程通知，不写入持久化文件或脚本 API；未携带来源的写入继续触发刷新。

来源沿原生执行入口及桥接返回传播，并非通用 JavaScript 异步上下文；脚本自行跨无关事件共享 Promise 时，延续代码可能沿实际唤醒入口归属。当前回归覆盖独立配置事件与正常原生异步调用，未覆盖任意跨事件 Promise 协调。若需要支持这类脚本，应单独明确其依赖和失效语义。
