# Agent Note: Widgee 生成 Widget 的背景铺满规则

Status: implemented
Archived: 2026-11-05

## 问题

生成的彩色 Widget 在聊天与资料库中出现宽白边：脚本给内容容器设置背景，宿主四周仍有 14pt 留白。教材只强调内容预算为外框尺寸减去 28pt，未说明背景和内容的覆盖范围不同。内置“22 社交提及”通过外框尺寸画布与根节点负 padding 铺满背景，证明现有 API 已足够。

## 决策

原生 Widgee 的常驻提示词要求背景覆盖整个 Widget，文字与按钮保持内部留白。常驻教材和按需 widget 参考使用同一份说明及完整计数器示例，明确修饰符顺序：内容 `.padding(14)` → context 外框 `.frame(...)` → `.background(color)` → 根节点 `.padding(-14)`。infinity frame 只填满宿主提供的内容区，不能代替这套布局。外框由宿主裁切，内部圆角卡片只用于设计明确需要的局部色块。

示例使用实际 context 尺寸，按小尺寸和宽尺寸组织内容，并将 accessory 留给独立紧凑分支，不套用负边距或强制彩色背景。参考 22 的背景机制，不复制其固定 170pt 画布和绝对坐标。教材继续约束内容高度、按钮和间距预算；铺满背景不意味着文字贴边。

提示词版本沿用 SDK 一致的已知版本会话继续或恢复时升级的机制；协议由 [Widgee 协议](../../../../docs/widgee-protocol.md)维护。历史读取、已发布源码和本地已采用脚本不因提示词变化而改写，用户修改并采用新版本后才更新样式。网页转 Widget 的提示词与接口不受影响。

[桌面一致性](2026-10-19-widgee-widget-preview-parity.md)继续拥有 14pt 宿主边距和共享布局；本记录拥有生成教材的背景规则。[聊天生成](../feature/2026-10-19-widgee-widget-chat.md)继续拥有 SDK 教材及发布机制，[资料库 UX](../feature/2026-10-19-widgee-tabbed-chat-library-ux.md)继续拥有快照与图片失效机制。上述记录仅部分延伸，均保持活跃，不归档或删除。

## 曾考虑的替代方案

**移除宿主的 14pt 边距。** 会改变所有已采用脚本的内容位置，已有 22 等负 padding 脚本还可能越界。现有能力已足够，保留宿主规则。

**只要求模型增加 infinity frame。** 只能填满内缩内容区，仍会露出宿主背景，无法解决截图中的白边。

**只补一条“背景铺满”的自然语言要求。** 自定义 SDK 缺乏模型先验，模型仍可能照搬 SwiftUI 的不存在 API。提供 modifier 顺序明确、可执行的完整示例。


## 验证

后端 Widgee 会话测试 24 项通过，涵盖 widgee-3 等已知版本升级、未知版本及 SDK 错配拒绝；真实 pi 工具与教材测试 3 项通过，包含常驻与按需参考的一致性。Swift 的 4 项教材和固定源码测试、1 项本轮真实生成源码检查通过；源码在运行时执行，不以语法校验代替渲染。

iPhone Air（iOS 27.0.1）上新增 2 项背景测试通过。测试目标将服务端的实际 example.ts 作为资源读取，三种 Home Screen 尺寸分别检查共享桌面容器、聊天预览和资料库缩略图的四边中点像素，避开圆角蒙版；共享容器与缩略图逐像素比较，每个 8 位通道允许 1 的抗锯齿取整差异。恢复为 infinity frame 且不补偿边距的原错误写法会被像素条件拒绝。移除固定外框后测量内容自然高度，确认内容能放进减去 28pt 的区域；accessory 分支没有 Home Screen 的补偿或背景。

真实后端与模型的 iPhone 聊天 E2E 通过：生成蓝色喝水 Widget、冷启动恢复、三种尺寸采用、修改为绿色并保留计数。主屏幕 App Intent E2E 通过，计数从 3 增至 4，回到资料库显示对应快照。截图核对聊天中尺寸、资料库大/小尺寸和主屏幕小尺寸，背景覆盖圆角外框，内容保留留白。新生成脚本名为“喝水QA-E1D142”；旧脚本仍保留原样。

同一真实模型 gpt-6.1-sol、同一深绿色喝水需求各运行一次：首轮输入从 8,327 增至 8,787 tokens（增加 460）；总输入从 51,019 降至 18,900，模型调用从 5 次降至 2 次，工具错误从 1 次降至 0。新输出采用完整背景布局并通过 Swift 校验。输入计入缓存 tokens；这是小样本，不能推断整体费用或成功率。

TypeScript、变更 Swift 的 strict lint、iOS 契约及负例、文档链接、Agent Notes 与 diff 检查通过。背景像素测试接入默认真机聊天测试脚本；独立运行方式见 [iOS README](../../../../ios/README.md#真机聊天生成测试)。

## 后果

[中尺寸内容预算](2026-10-20-widgee-medium-content-budget.md)针对多段内容超高补充生成教材与渲染回归，保留本记录的背景配方和宿主边距。

背景规则与已有脚本能力一致，不改变宿主边距或原生渲染 API，减少模型凭 SwiftUI 先验猜测修饰符的机会。代价是教材增加 460 个首轮输入 tokens，并继续依赖共享宿主的 14pt 规则；未来调整宿主时必须同步教材、示例与像素回归。

提示词无法保证任意生成结果的布局。回归约束教材与渲染规则，真实模型样本提供额外证据；不能据此宣称系统着色、全部字体与锁屏布局逐像素一致。任意脚本的超大辅助字号溢出仍是独立问题。

已采用 Widget 不自动重新生成或改写。新版本需要用户发起修改和采用，保持既有业务状态及用户编辑的控制权。
