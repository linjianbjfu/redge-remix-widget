# Agent Note: Widgee 配置保存后的预览与桌面刷新

Status: implemented
Archived: 2026-11-05

## 问题

用户保存倒计时事件“旅行出发”后，资料库仍展示默认的“期待，下一刻”，桌面 Widget 也没有及时刷新。资料库从中尺寸改为小尺寸后，点卡片打开的配置页仍展示全宽内容，无法核对小尺寸成品。

设备中的事件配置和 `preferredFamily: small` 均已保存。对应小尺寸快照包含“旅行出发”，源码哈希和实测宽高匹配。`LibraryWidgetCard` 的刷新条件不包含配置保存或快照更新，关闭运行 sheet 也没有显式刷新通知。`storage` 写入不通知 WidgetKit；仅保存资料库源码才请求刷新时间线。

倒计时脚本的 `render()` 返回完整配置表单，`widget()` 才按 family 渲染小组件。运行页只展示 `render()`，没有所选尺寸的 Widget 预览，不能靠改变表单外框解决尺寸问题。

## 决策

运行页提供独立的 Widget 预览区域，使用当前应用的 `preferredFamily` 和共享 Widget 布局容器，配置表单保持正常宽度和滚动。生成提示词及教学示例要求 render() 只提供设置、权限、操作与反馈，导航标题和成品预览由宿主提供，避免重复展示标题、介绍或当前内容卡。已保存脚本由用户请求修改源码，宿主不按文案或节点位置裁剪任意视图树。进入页面、状态更新及保存配置后刷新预览；配置表单上方的预览不执行桌面 App Intent。无 `widget()` 的应用保留普通运行页。省略 render() 的纯 Widget 使用独立交互路径，见[详情页尺寸与可选配置页](../feature/2026-10-19-widgee-widget-detail-controls.md)。

运行中状态的 Widget 投影入口调用当前脚本的 `widget(state, context)`，不重设 initialState、不重复 onAppear、不切换现有运行实例的 headless 状态，不破坏表单事件处理器。现有 `renderWidget()` 会重置状态与处理器，不能直接用于活动中的配置页。投影保留未注册到活动实例的处理器占位符，维持原生按钮样式和节点路径；直接移除函数属性会让按钮退化为文字，桌面 App Intent 仍按节点路径重建真实处理器。异步投影串行并合并更新，结果绑定运行请求、源码、尺寸和状态版本；退出页面、删除或源码更新后的迟到结果不得覆盖新内容。

投影等待超时或持续被新状态取代时停止自动投影，避免脚本持续更新造成循环。快照生成期间暂缓完成按钮和下拉关闭；失败保留表单与上次成功内容。异步等待超时只停止预览；同步 JavaScript 执行超时仍服从运行时整体终止保护。

成功的运行预览形成带来源信息的本地快照，并使该应用的缩略图失效。返回资料库时重新检查匹配快照，不依赖切换 Tab 或前后台。快照代表脚本当前状态；哪些输入已经保存仍由脚本的 storage 与状态管理负责。生成失败保留上一次成功内容并显示错误，不用默认 stub 冒充新配置。聊天及源码编辑器的隔离预览规则保持有效，滚动资料库不启动真实桥接。

原生 storage 成功写入后通知主应用，覆盖 set、remove、clear，失败写入不通知。运行预览按[缓存写入的刷新来源](2026-10-22-widgee-preview-storage-feedback.md)忽略自身写入的通知，配置及其他来源继续触发更新。主应用核对应用身份与真实共享目录，更新运行预览及资料库，并合并 Widgee Widget 时间线重载请求；无需模型生成的脚本新增刷新调用，也不依赖脚本按钮的文字。

WidgetKit 公开重载接口按 kind 工作，目前所有 Widgee Widget 共用一个 kind。因此使用该 kind 的重载保证当前编辑应用的桌面实例收到刷新请求，可能同时调度其他 Widgee 实例；不能承诺只刷新一个 appID。时间线仍按各实例配置的应用 ID 和实际 family 读取已保存数据，资料库偏好不改变桌面尺寸。连续保存合并请求，不轮询或持续请求刷新；实际显示时间服从系统调度。

本记录延伸[可视化资料库](../feature/2026-10-19-widgee-tabbed-chat-library-ux.md)的缓存更新机制，保留[预览与桌面一致性](2026-10-19-widgee-widget-preview-parity.md)的共享布局及隔离预览规则，并遵守[运行身份](2026-10-19-widgee-run-presentation-identity.md)的实例隔离。三篇仍拥有独立约束，保持活跃，不归档或删除。当前职责与时限由 [iOS 设计](../../../../ios/DESIGN.md#资料库缩略图)维护，复现入口见 [iOS README](../../../../ios/README.md#真机配置与刷新测试)。

## 曾考虑的替代方案

**仅在关闭配置页时清除缩略图。** 可重新读到已有正确快照，但没有匹配快照时仍会显示默认示例，也不能更新桌面时间线。

**启动另一份完整运行时反复读取配置。** 可以复用 WidgetRunner，但每次会执行 onAppear，可能重复请求数据或写入存储。活动配置页优先投影现有状态，桌面继续独立从持久化配置运行。

**把配置表单缩成小尺寸。** 会截断输入框和保存按钮，且仍不代表 widget() 的布局。预览与表单需要分开呈现。

## 验证

连接的 iPhone Air（iOS 27.0.1）通过 18 项 XCTest 单元与集成测试，覆盖配置持久化与初始化次数、重复投影后的表单处理器、按钮像素一致性及桌面操作重建、落盘后通知、失败写入不通知、刷新合并、隔离目录拒绝、迟到状态与替换源码拒绝、停止运行和持续更新保护，以及现有资料库、运行身份、手动天气地点和布局回归。竞争用桥接 barrier 控制，测试数据按随机应用 ID 隔离。

完整倒计时 UI E2E 通过：中尺寸改小、配置页的小尺寸预览、修改并保存事件、返回列表看到新图片、主屏幕实际显示新标题、恢复原事件、冷启动及桌面再次核对。截图确认列表与桌面显示相同事件及布局。手机上的原名称“旅行出发”和小尺寸偏好已恢复。自动化文本选择、空输入框值及系统转场造成的探索失败不计为通过；测试等待稳定元素位置，并区分刷新请求断言与桌面内容断言。

Swift Package 的 8 项 WidgetRunner／WidgetResult 测试、iOS 契约及 7 项非法输入检查、文档与 Agent Notes 门禁通过。应用层变更、新文件、StorageModule 和 Widget 扩展的 SwiftLint strict 通过；MiniAppRuntime、MiniAppHost、SharedContainer 与 HEAD 比较无新增 lint 诊断，但仍有既有行长及文件／类型长度告警，不把全量 strict 记为通过。

配置展示回归通过：手机中现有倒计时移除重复标题、介绍和当前事件卡，保留事件、目标日期、小尺寸偏好与 widget() 布局。真机 UI 测试确认预览内出现已保存事件且整页仅一处同名静态文本，重复区域消失、保存按钮可见；源码样本纳入 SDKTeachingTests。教材回归覆盖空配置和已有配置，恢复重复展示的负例确实失败。后端 25 项测试及类型检查通过。系统提示词按字符数 / 4 估算从 9,059 增至 9,106 tokens（不含工具），本轮未重新调用云端模型验证生成分布。

## 后果

配置页能核对真实 Widget 外观，成功投影无需先安装主屏幕实例就能更新资料库图片。快照代表脚本当前状态，哪些字段属于已保存配置由脚本负责；宿主不能推断未提交草稿。投影仍执行脚本，超时保护不构成不可信 JavaScript 沙箱。

WidgetKit 可以延迟或合并重载请求，本次真机观察不能提供秒级刷新保证。应用偏好不改变已放置实例的实际尺寸。真实天气仍受独立的 WeatherKit 服务授权问题影响，本记录不宣称该服务已修复。后端协议保持不变；生成提示词版本与兼容升级规则由[客户端协议](../../../../docs/widgee-protocol.md)维护。提示词只约束后续生成，不能自动移除旧源码里的重复布局。
