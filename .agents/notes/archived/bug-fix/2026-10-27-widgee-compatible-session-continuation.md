# Agent Note: Widgee 兼容旧会话继续生成

Status: implemented
Archived: 2026-11-05

## 问题

当前客户端能预览兼容旧 SDK 的 Widget，却不能在其原会话继续修改。ChatStore.compatible 要求请求和会话的 SDK 都等于部署版本，新增 API 引起 SDK 内容哈希变化后，已升级客户端也会收到 sdk_mismatch。更新应用无法解决会话自身的版本限制。

2026-10-27 只读检查真机缓存，定位到“周五倒计时小组件”会话 `58a672b9-57fa-441e-880e-7a25fdd40c1f`。它于北京时间 2026-10-26 19:00 创建，SDK 为 `1cecd293a8b590051277ce73a5b3fe5dd92f87edb8b8d6d358feb0a2ed530288`，提示词为 widgee-14，最后一轮已完成。当前 SDK 为 `54a224c46742a2ad74896ba39bc200cd5ec03eb2f6d449366c658a6be480c0c6`。旧版本在产物兼容表内，widgee-14 也受支持，只有会话 SDK 相等条件不满足。缓存完整性检查通过；未向用户会话发送测试消息，未修改手机或线上数据。

## 决策

旧会话和旧客户端都允许续聊。聊天服务端不再把 SDK 或提示词版本作为兼容准入条件，也不维护旧版本名单。创建会话和提交新 turn 仍要求 sdkRevision 为合法的 64 位十六进制哈希；只校验格式，不判断是否等于当前版本或是否出现在已知版本表中。同输入 turn 重放保持现有幂等规则。

每次接受新 turn，在同一事务中将会话 SDK 和提示词记录更新为当前生成器版本；恢复执行时也使用当前生成器。保留会话 ID、聊天和模型历史及当前 Widget，历史产物的 SDK、源码和哈希不变，新产物标注实际生成版本。每轮现有流程重新加载当前系统提示词、参考目录和工具，再恢复原模型历史。

读历史与同输入重放不升级、不额外生成。运行中任务阻止接受另一轮；升级和接受消息共同回滚。接受后的模型失败保留消息和升级版本。消息摘要及目录增量同步新版本，使客户端缓存收敛。

客户端现有产物校验保持有效。允许旧客户端发起生成不承诺其能运行新 SDK：服务端不维护旧版生成器、不伪造产物 SDK、不按旧客户端裁剪 API。图库投稿的 SDK 检查属于另一接口，本次不改变。

此决策调整[原生聊天](../feature/2026-10-19-widgee-widget-chat.md)的固定 SDK 规则，补上[兼容产物预览](2026-10-20-widgee-compatible-artifact-preview.md)未覆盖的续聊。两篇旧笔记继续保留其隔离、不可变历史和产物兼容决策，不归档。同步[协议](../../../../docs/widgee-protocol.md)。

## 曾考虑的替代方案

**要求新建会话。** 丢失原会话连续修改入口，不能满足兼容旧会话继续聊的需求。

**使用已知旧版本名单放行。** 用户选择所有旧会话和旧客户端都可续聊，因此不再维护逐版本兼容名单。输入格式仍校验，历史来源和请求幂等仍受保护。

**批量重写会话和产物 SDK。** 破坏历史来源并影响运行中任务。按需升级会话、保留历史产物能限制修改范围。

**保留每个历史 SDK 的生成器。** 可支持旧客户端，但需要长期维护多套提示词、参考和校验器；本次不引入多版本生成服务。

## 验证

回归测试先在修复前复现三种请求失败：旧客户端创建、当前客户端续聊旧会话、未登记合法客户端创建均返回 409。修复后，聊天、图片、目录增量和本地化五个文件的 86 项测试通过；补充大小写及历史不可变断言后，相关两个文件的 28 项测试通过。覆盖缺失或非法请求版本、旧会话空版本、未登记版本、运行中任务、重复和冲突重放、事务回滚、失败后历史产物与模型记录保留。

`node --test backend/src/agent/widgee.node.test.mjs backend/src/agent/widgee-images.node.test.mjs` 的 4 项测试通过，使用真实 pi SDK 与隔离模型响应服务，验证旧会话恢复时加载当前提示词、保留五张图片、恢复旧版已接受任务且只写一条用户消息。此层不声称调用了线上模型。

2026-10-27 部署 Worker 版本 `6497c3c5-47c7-45dc-9379-f8d749bb3ea1` 至生产环境。独立测试会话使用旧客户端 SDK `1cecd293…` 创建成功（201），真实模型生成周五倒计时后，在同一会话完成第二轮改色；两轮均 completed，新产物为当前 SDK，第一版源码和 SHA-256 未变。测试会话删除返回 204，证据保存在 `.playwright-mcp/session-compatibility/`。线上测试验证旧客户端请求，旧会话持久化版本升级由模块和 runner 回归覆盖；未向用户原会话发送测试消息。

类型检查、文档与笔记门禁以及 git diff 检查通过。没有修改客户端运行时或产物读取名单，没有启动本地任务 server，也没有提交或推送此次修复。

## 后果

旧客户端可发起生成，但其产物兼容检查可能拒绝当前 SDK，或无法运行新增 API。本次不改变客户端能力及产物读取策略，不提供旧版本生成器。SDK 内容哈希不能比较新旧，格式合法的未登记版本也会被接受。

历史模型上下文被保留，当前系统提示词与工具由每轮运行加载。版本升级不能保证任意历史工具结果与未来生成器语义兼容；如将来出现真正破坏性变化，应单独定义迁移，而非恢复所有版本必须相等的限制。
