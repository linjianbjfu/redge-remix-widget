# Agent Note: Widgee 中尺寸生成布局的内容高度预算

Status: implemented
Archived: 2026-11-05

## 问题

“前往龙岗路 12 号”和“微软股票 · Yahoo Finance”的中尺寸 Widget 底部被裁切。iPhone Air 的已保存视图树经实际 SwiftUI 渲染复现：外框为 338 × 158pt，宿主四周留白 14pt，内容高度预算为 130pt；移除根节点背景、固定外框和 padding 后，默认字号下的内容自然高度分别为 148pt 和约 149.7pt。路线说明和股票更新时间落到外框之外。

路线脚本在所有非小尺寸中使用 56pt 时间数字；股票脚本纵向叠放双行标题、行情区和页脚。字体行高、各层间距和 Spacer 共同超出预算。路线的默认 Spacer 测得最小高度 8pt；股票虽使用零最小高度 Spacer，仍有相邻 VStack 间距，单独移除弹性留白不足以修复。

教材中的高度限制需要配合多段内容示例：背景覆盖、内容预算和中尺寸信息取舍是不同的布局约束，单一计数器不足以说明标题、多项指标和页脚如何共存。

## 决策

原生 Widgee 常驻教材及其共用的按需 widget 参考分别说明背景覆盖与内容预算。共享宿主尺寸、14pt 留白及背景铺满机制保持一致；网页转 Widget 的提示词独立维护。

模型根据 context 实际尺寸扣除宿主留白，为中尺寸单独组织紧凑布局。标题和页脚优先预留高度，主体使用横向分栏或同行标签与数值；双行标题、额外指标和大字号按空间取舍，不能用“非 small”统一套用 large 布局。预算包括字体实际行高、各层间距、内部 padding 与 Spacer 最小高度；零高度 Spacer 两侧的间距也计入预算。加载、空数据、错误与配置状态遵守同一约束。

[布局示例](../../../../backend/src/widgee/layout-example.ts)提供标题、主指标、辅助指标和页脚的完整源码，与常驻教材和按需参考共用。紧凑状态说明允许换行；主要数值保持完整，额外详情属于大尺寸。原生高度回归直接执行此教材，移除固定外框后测量内容，避免外框裁切掩盖超高；原错误组合是同一预算的负例。背景边缘像素检查覆盖此示例。

提示词版本与旧会话升级由 [Widgee 协议](../../../../docs/widgee-protocol.md)维护。历史和已采用脚本不因教材更新而改写，已有 Widget 通过原会话生成修订，由用户预览后采用。两个案例的修订保留数据获取、存储键、路线配置与操作；测试没有替换设备上的已采用版本。

[背景铺满规则](2026-10-19-widgee-full-surface-background.md)继续拥有根节点背景配方；[预览与桌面一致性](2026-10-19-widgee-widget-preview-parity.md)继续拥有共享宿主与实际尺寸。本记录拥有多段内容的教材与高度回归，未取代两篇独立决策，均保持活跃。

## 曾考虑的替代方案

**扩大预览或移除宿主边距。** 会让预览偏离桌面，或改变所有已有脚本的布局；脚本本身超高，宿主规则没有错误。

**统一缩放所有生成内容。** 会降低文字可读性，也掩盖没有按尺寸组织信息的问题。脚本应选择适合该尺寸的结构。

**只修改两个脚本或再补一句“不要溢出”。** 前者不能影响后续生成，后者与已有教材重复。具体预算规则、可执行示例与渲染负例共同约束教材，真实模型案例验证生成效果。

## 验证

后端 `src/widgee/chat.test.ts` 29 项通过，覆盖新增示例源码及已知旧提示词版本升级；真实 pi 工具与教材测试 3 项通过，确认常驻与按需教材一致。Swift `SDKTeachingTests` 7 项通过，本轮配置真实生成产物目录，源码验证没有跳过。

iPhone Air（iOS 27.0.1）的 `WidgetLayoutTests` 与 `WidgetBackgroundTests` 共 4 项通过：15 个尺寸与状态组合覆盖小、中、大、长数值、加载、无数据、失败和配置提示；超高路线、超高行情与内缩背景对照均被相应断言拒绝。默认真机聊天脚本包含这些回归，独立运行见 [iOS README](../../../../ios/README.md#真机聊天生成测试)。

独立渲染的原背景图片逐字节比较出现不稳定差异。导出原 PNG 后比较 RGBA：158 × 158 图像中 34 个通道值不同，最大差为 1，分布在文字、按钮和外框抗锯齿边缘。背景回归改为同尺寸的逐像素比较，每个 8 位通道容差为 1；内缩背景负例仍必须失败。最终真机回归使用该比较通过，不依赖重试获得结果。

两个原会话使用新教材由真实模型生成修订，服务端版本均为 widgee-9；源码的 widget 生命周期之前部分逐字相同，配置及数据获取逻辑保持有效。原样修订在 iPhone 上通过 18 个案例与状态、尺寸组合的运行和高度检查，中尺寸内容均为 130pt，截图显示完整路线说明和行情底栏。状态注入使用隔离测试模块，不读取或改写本地配置。真实聊天 UI 测试通过两个原会话的最新中尺寸预览，MSFT 使用实际 HTTP 行情，路线按聊天隐私规则显示未配置状态；成功路线的布局由注入配置单独验证。临时诊断与案例 UI 测试已清理，修订草稿保留在原会话供用户采用。

同一 gpt-6.1-sol、用户问题与工具定义的真实网关请求，首轮输入从 9,317 增至 10,032 tokens，增加 715。此测量描述教材的输入成本，不代表整体生成成功率或总费用。TypeScript、变更 Swift 的 strict lint、SDK 一致性及负例、iOS 契约、文档链接、Agent Notes 和 diff 门禁通过。

## 后果

模型得到可执行的多段内容布局示例，并明确中尺寸不能沿用大尺寸纵向密度，代价是增加首轮上下文成本。宿主留白变化时必须同步教材和高度回归。

提示词和示例不能证明任意生成脚本、任意内容或所有辅助字号都不会溢出。验证针对默认字号与明确测试数据，不新增全量脚本自动布局校验服务；如真实生成仍频繁失败，再评估发布前渲染验证。高度通过也不能单独证明文字没有被横向截断，验收同时核对截图。

紧凑布局可减少中尺寸的次要信息，优先保留关键数值、单位与必要状态。旧 Widget 需要用户采用修订才会改善，提示词发布不自动修复旧源码。真实权限授权和导航打开未在本轮重复执行，相关处理源码保持不变；桌面未自动采用修订，也未声称已在主屏幕替换验证。

字号层次与富余空间利用的后续调整见[生成布局可读性](2026-10-21-widgee-readable-widget-layout.md)；本记录的内容预算与防裁切约束继续有效。
