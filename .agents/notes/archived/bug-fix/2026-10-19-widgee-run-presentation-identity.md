# Agent Note: Widgee 运行页与启动请求的身份绑定

Status: implemented
Archived: 2026-11-05

## 问题

资料库快速切换小应用时，选中的名称与实际运行的 JavaScript 不一致。iPhone 诊断日志中，点击喝水后 sheet 参数和视图初始化都收到喝水的 ID，但启动的 host 仍属于天气。资料库中的稳定 ID 与源码对应正确；固定的运行页身份保留了 `@State host`，新传入的应用值不能替换这个实例。

## 决策

[RunPresentation 与 RunnerView](../../../../ios/Widgee/Views/RunnerView.swift)将启动身份和持久化身份分开。每次卡片点击或深链打开创建一个请求，持有新的 UUID、小应用值快照及该快照对应的完整 MiniAppHost。运行页直接使用请求的 host，不再另存一份可残留的 host 状态。

[RootView](../../../../ios/Widgee/Views/RootView.swift)以请求作为 sheet item，运行内容也以请求 UUID 标识视图生命周期。同一呈现位置替换请求时，新实例启动、旧实例停止；同一应用重新打开或从 Widget 深链返回也重新读取存储。稳定应用 ID 继续决定存储目录，启动 UUID 不参与持久化。当前运行流程由 [iOS 设计](../../../../ios/DESIGN.md#编辑校验与运行)维护。

[原生运行时与通信基础](../feature/2026-10-19-widgee-ios-native-runtime.md)继续拥有运行时移植、稳定应用 ID 与存储设计。此修复不改变它们，也不改变聊天预览与 Widget 扩展的独立运行机制；没有取代或归档其他活跃笔记。

## 曾考虑的替代方案

**仅用稳定应用 ID 标识运行页。** 可以区分不同应用，但同一应用的 Widget 深链也需要重读已改变的存储；启动请求身份同时覆盖两种情况。

**每次点击同时更新独立的 runID 和 running。** 可以触发实例重建，但应用值和启动身份仍由两个状态表达。单一请求让页面只能接收完整的一次启动。

**在现有 host 上替换源码。** host 同时持有应用 ID、桥接上下文和存储目录，只换源码不能保证应用隔离；新启动拥有自己的完整实例。

## 验证

[RunnerTests](../../../../ios/WidgeeTests/RunnerTests.swift)在 iPhone 上通过两项测试：启动快照与实例隔离，以及同一个 UIHostingController 中连续替换运行请求。后者实际执行天气、喝水、天气重开和同 ID 的源码修订，检查正文、旧实例停止及按应用隔离的持久化计数。临时将运行内容恢复为固定视图 ID 时，该测试拒绝未启动的新脚本和未停止的旧实例；恢复实现后通过。

连接的 iPhone 上，前三个现有应用完成 9 次卡片切换，交替使用完成按钮与下拉退出；随后通过系统 URL 打开执行 6 次深链切换，包括同一应用重复打开。标题与脚本正文对应。设备专用诊断测试和日志代码不进入正式实现。

SwiftLint、iOS 移植契约及其非法输入检查、文档链接和 Agent Notes 门禁通过。

## 后果

[配置与 Widget 刷新](2026-10-19-widgee-configuration-widget-refresh.md)扩展运行页的真实状态预览与配置保存通知，继续保持此处的布局和运行实例约束。

运行实例的身份在启动时确定，名称、源码、桥接上下文和存储目录来自同一个应用快照。每次打开都会创建新实例，内存状态不会跨启动保留；需要恢复的业务状态仍由脚本写入稳定应用 ID 下的 storage。资料库格式、脚本 API 与后端协议不变。

视图消失与异步启动可能交错，仍依赖 MiniAppHost 的停止和迟到回调保护；启动身份不能替代运行时内部的并发隔离。普通的逐个打开测试不能覆盖同一呈现位置保留旧实例的问题，因此保留直接替换已挂载视图的回归测试。
