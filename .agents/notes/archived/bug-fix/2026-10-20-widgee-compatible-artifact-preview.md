# Agent Note: Widgee 兼容旧 SDK 的产物预览

Status: implemented
Archived: 2026-11-05

## 问题

“GitHub 风格年度剩余天数”会话的产物“今年还剩 · Year in Pixels”原本可预览，加入地图 API 后被客户端拒绝。实际下载源码为 3757 UTF-8 字节，字节数和 SHA-256 均与服务端一致，也通过当前服务端源码校验。失败发生在 ChatPayload.verifiedSource 对 SDK 哈希的完全相等检查，尚未执行 JavaScript。

产物 SDK 为 `e6f14781d00c623079f171ab0f6634c5b805e7ec64bfca67464768c1b985e102`，当前 SDK 为 `de1a38c547e7bc3959e1a29d36c4297344c909e5a03c84e7d152c04883abfb40`。两份 SDK 的差异只有 maps.snapshot、地图模块说明与关键词，以及相应生成声明。旧 API 未被删除或改变，但完整文档内容哈希无法表达这种向后兼容关系。

## 决策

分离产物的完整性校验与运行时兼容性校验。源码非空、128 KiB 上限、UTF-8 字节数和 SHA-256 验证保持必需；缺失或不匹配时显示完整性错误。版本不兼容使用独立诊断，不再让用户误以为重新下载可以修复 SDK 错配。

增加明确的、单向的产物兼容记录：当前 SDK 可以读取自身，以及本次审查的上一版 SDK。记录绑定完整 source revision 和 target revision，由 SDK 生成流程生成客户端读取策略；顶层 SDK 门禁验证目标必须等于当前 SDK，未来 SDK 再变化时必须重新审查，不能自动继承或传递兼容性。未知、缺失、未来版本继续拒绝；不回退为“只要源码能跑就放行”。

聊天预览和用户主动添加使用同一产物校验策略。添加仍需现有离线运行校验；不会因为版本在兼容表中就省略源码校验。服务端的历史、不可变产物 SDK 标记、字节数和哈希均保持原值，不重新生成，也不伪装为新版本产物。

产物读取与生成请求的准入分别维护。[旧会话续聊](2026-10-27-widgee-compatible-session-continuation.md)允许旧客户端和旧会话使用当前生成器，定义会话版本更新、模型上下文保留和幂等处理；不会通过改写历史产物版本实现兼容。

[兼容策略](../../../../backend/scripts/widgee-artifact-compatibility.json)由 SDK 生成器和验证器共同读取，生成完整的客户端 SDKRevision；门禁比对完整生成文件，防止当前哈希正确但允许列表漂移。[Widgee 协议](../../../../docs/widgee-protocol.md)拥有读取产物与生成会话的区别。

此决策部分调整[地图 API](../feature/2026-10-20-widgee-map-snapshot-api.md)的产物读取策略；[原生聊天](../feature/2026-10-19-widgee-widget-chat.md)及[聊天预览](../feature/2026-10-19-widgee-chat-title-preview.md)的服务端历史、完整性、隔离和采用约束仍有效。

## 曾考虑的替代方案

**移除全部 SDK 校验，只运行源码。** 无法识别未知或语义不兼容的运行时；某次渲染成功也不能验证未执行分支和后续交互，因此不采用。

**重写旧产物的 SDK，或重新生成 Widget。** 修改版本标记破坏不可变产物的来源信息；重新生成会产生额外费用及内容变化，且不能解决其他旧历史预览问题。

**立刻引入能力协商和语义化运行时版本。** 能处理更复杂的演进，但需要协调服务端会话、客户端和生成协议。当前有明确且仅新增能力的一对 SDK，先用有审查边界的单向兼容记录恢复旧产物；保留以后替换读取策略的空间。

## 后果

兼容性声明需要同时审查 API 和运行时行为，单纯 API 名称集合包含不能证明语义兼容。显式目标绑定防止未来破坏性更新意外沿用此声明，但不替代回归测试。当前只确认这一版旧 SDK；其他未知版本不会自动解封。

服务端允许继续生成不代表旧客户端能运行新产物。产物版本与完整性检查仍有独立职责，不能把请求获准宣传成运行时能力升级。

## 验证

2026-10-20 在 iPhone Air（iOS 27.0.1）通过 24 项单元及集成测试：SDKArtifactTests、ChatTests、ChatPreviewTests、LibraryUXTests。原年度产物作为固定 fixture，覆盖小中大尺寸运行、预览、采用与尺寸持久化；损坏源码、未知版本不能启动渲染或替换已有内容；兼容版本的运行异常仍阻止采用。完整性与版本诊断分别覆盖空源码、超限、哈希、字节数和缺失字段。

真机 SDKArtifactE2ETests 直接打开原“GitHub 风格年度剩余天数”会话，通过三种尺寸切换及冷启动恢复。四张测试截图均显示年度 Widget，无 SDK 错误。测试未发送生成请求、未更改已采用 Widget。真机测试曾因锁屏等待，解锁后本轮全部通过。

`npm run verify-widgee-sdk` 通过，实际执行目标过期、无效或重复旧版本、当前版本重复、策略未重新生成、Swift 策略漂移等拒绝用例。`npm run verify-docs`、`npm run verify-notes`、改动 Swift 文件的严格 SwiftLint、脚本语法检查及 `git diff --check` 通过。
