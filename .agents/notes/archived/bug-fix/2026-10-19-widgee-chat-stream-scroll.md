# Agent Note: Widgee 聊天流式更新的滚动稳定性

Status: implemented
Archived: 2026-11-05

## 问题

逐字调用 `scrollTo("bottom", anchor: .bottom)` 会在短聊天中与顶部安全区的位置修正冲突。iPhone Air（iOS 27.0.1）的真实 ChatView 事件重放中，无 Widget 的短聊天出现 17 次超过 5pt 的向上位移，最大 122pt；含一个 Widget 的短聊天出现 47pt 位移，跳动时内容高度不变。临时关闭逐字滚动消除位移，但同时失去长回答的自动跟随，因此不能直接作为修复。

流式正文与正式消息使用不同排版，落盘还会改变标题、内边距及行宽。无条件滚动也会抢走用户阅读历史的位置；同一会话重新加载时，需要恢复跟随，不能只依赖会话 ID 改变。

## 决策

[ChatScrollView](../../../../ios/Widgee/Chat/ChatScrollView.swift)拥有客户端底部跟随状态，使用包含安全区的真实几何数据判断是否需要定位。短内容保持顶部；长内容按布局变化跟随，用户手势与程序定位分别处理。具体跟随阈值、恢复时机和文字排版由 [iOS 设计](../../../../ios/DESIGN.md#后端通信边界)维护。

几何状态对象不驱动页面重新计算；需要定位时才发出视图任务，任务读取最新跟随状态，使手势可以覆盖尚未执行的定位。原有 LazyVStack 保留，避免提前布局整份历史。流式与正式 assistant 消息共用呈现函数，不改变服务器正文、seq、游标或生成请求。

[横向定位约束](2026-10-29-chat-horizontal-scroll.md)拥有 Y 坐标定位与消息目标布局的选择；本记录继续拥有纵向跟随策略。键盘和前后台布局重算的回归需同时检查两个轴。

预览加载与成功状态使用同尺寸宿主；无 Widget 的场景也能复现，因此预览重新渲染不是本次修复的依据。保留可见性、缓存、stub 执行与显式采用规则。

取代检查保留[会话命名与预览](../feature/2026-10-19-widgee-chat-title-preview.md)、[底部导航与资料库](../feature/2026-10-19-widgee-tabbed-chat-library-ux.md)和[预览布局一致性](2026-10-19-widgee-widget-preview-parity.md)。它们仍分别拥有预览隔离、会话生命周期及共享尺寸；本记录拥有滚动策略，无归档或删除。

## 曾考虑的替代方案

**直接删除流式自动滚动。** 真机对照能消除跳动，但长回答会增长到屏幕之外，用户无法持续看到最新内容。只用于确定原因。

**只给逐字 scrollTo 加节流或动画。** 降低频率仍会对短内容发出不必要的底部定位，也不能解决用户读历史时被拉回的问题。

**优先缓存预览视图或将 LazyVStack 全部改成 VStack。** 无 Widget 也能复现，预览不是必要条件；全部提前布局还会增加长历史开销。保留懒加载，以滚动控制修复有真机对照证据的原因。

## 验证

iPhone Air（iOS 27.0.1）通过 22 项单元与集成测试：4 项滚动状态测试、4 项真实页面布局测试、6 项预览测试和 8 项聊天测试。布局测试使用独立窗口、资料库和偏好设置，经 ChatModel.apply 重放 150 个文字片段，用 CADisplayLink 采集真实 UIScrollView。短聊天、一个 Widget、八个 Widget 历史、预览报错各采集 375 帧，流式阶段最大反向位移均为 0pt，末尾定位误差小于 0.5pt；正文落盘高度不变，最终 Widget 插入后到达底部。

临时恢复旧 ChatView 后，同一个短聊天回归测试分别以 122pt 顶部越界和 122pt 反向位移失败，证明检查能拒绝原缺陷。

真实后端与模型的 UI E2E 通过：首轮生成、键盘收起、三种尺寸预览、添加到资料库、继续修改、吐字期间上滑阅读、生成结束后返回底部，以及离开底部后重新打开同一会话。阅读期间旧消息位置保持在 1pt 误差内；历史恢复截图显示最新绿色 Widget。恢复跟随修复前失败的历史用例不计入通过。

[真机脚本](../../../../ios/scripts/test-chat-device.sh)默认包含新增测试，过滤运行方法由 [iOS README](../../../../ios/README.md#真机聊天生成测试)维护。逐帧 JSON 和截图保存在 xcresult 附件。本轮最终结果为 `/tmp/Widgee-scroll-fix-d.xcresult`，负例为 `/tmp/Widgee-scroll-negative.xcresult`。手机恢复原服务地址和用户身份，安装版本包含修复。

SwiftLint strict、iOS 契约与 7 项负例检查、文档链接、Notes 和 diff 检查通过。UI 验收针对该 iPhone 的默认字号与竖屏，不把它视为所有系统和辅助字号的全覆盖。

## 后果

短聊天不再因无效的底部定位上下往返；长回答继续自动跟随，阅读历史时则保持位置。跟随是本地视图状态，历史重新加载和主动发送会恢复最新位置，不承诺持久保存用户上次读到的位置。

SwiftUI 懒布局会修正内容高度，不能仅按文本长度推断滚动距离。未来修改聊天容器、安全区、字体或结果卡片时，需要同时运行逐帧布局和真实手势回归；仅验证最终截图无法发现吐字期间的往返位移。
