# Agent Note: 广场单表状态与更新时间同步

Status: implemented
Archived: 2026-11-05

## 问题

发布表的自增 ID 只表达新增，不能传递已有投稿的拒绝与删除。客户端因此需要遍历缓存核对，服务端还维护独立删除字段。用户要求单表保存生命周期状态，以 update_at 增量同步全部状态变化。

## 决策

shared_widgets 保留投稿 ID 与单一生命周期，不使用 published_widgets 或 deleted_at。status 包含 pending_translation、pending_thumbnail、pending、approved、rejected、deleted；语言表不拥有独立公共同步游标。删除保留元数据，该终态阻止审核或生产重试复活。语言生产、发布及原始/派生产物路径由[双语产物](../../implemented/feature/2026-10-23-shared-widget-localization.md)拥有。

update_at 为非空整数，并建立唯一索引。插入、语言产物或公开引用提交、实际状态改变，在同一 D1 事务中取当前毫秒时间与全表最大 update_at 加一的较大值。每次分配改变一份投稿；重复成功结果不推进时间。它兼具更新时间与严格递增同步版本，写入密集或时钟回退时可略领先墙上时间。保留删除行保证最大值不会回退，不增加计数表。所有业务写入入口包括分类保存和导入都遵守该分配方式。未发布本地数据的一次性分类重审例外及缓存重建由[分类审核](../feature/2026-10-25-shared-widget-categories.md)记录，不适用于在线客户端增量同步。

公开列表使用 `?update_at=0&limit=20`，按 update_at 升序读取严格大于游标的行。响应包含 id、status、updateAt；只有 approved 附带名称、截图和代码的摘要，其他状态只返回同步标记，不暴露待审内容、作者或拒绝原因。客户端按投稿 ID 合并 approved，遇到其他状态移除卡片与图片；目录与本页最后 updateAt 原子保存，即使整页都是移除标记也推进。已采用资料库副本保留，来源身份继续使用同一个投稿 ID。

移除 `/check` 与 after_id 协议。图片、代码和详情使用投稿 ID，仍仅允许 approved。新客户端使用新缓存版本，从零建立目录；旧缓存不当作新时间游标，已经采用的资料库不重建。部署须协调后端与客户端升级，旧客户端不兼容新列表格式。

增加迁移重建 status 约束、把已有 deleted_at 转为 deleted、为所有行分配不同 update_at，保留其余元数据与 R2 路径后删除发布表及旧字段；不改写已经应用的迁移文件。Admin 保留删除确认、失败重试与待清理提示。

导出格式 v6 保存父记录、语言记录及所有私有引用产物，兼容 v1–v5，具体兼容、写入协调和公开重建由[导入导出](../process/2026-10-22-gallery-data-transfer.md)维护。合并保留目标已有分类、状态、译文与版本；新导入记录分配目标 update_at，不复制源游标，不恢复已删除记录。

严格递增时间分配保证单字段游标的分页正确性；Worker 与导入脚本共用 update-time.ts 中的 SQL 表达式。

### 与现有决策的关系

[分享与审核](../feature/2026-10-22-widget-gallery-sharing-moderation.md)的不可变产物、权限和采用规则继续有效；双表及发布游标由本记录取代。[Admin 删除](../feature/2026-10-22-admin-gallery-deletion.md)的确认交互、终态和 R2 清理继续有效，删除字段及缓存核对被替换。[导入导出](../process/2026-10-22-gallery-data-transfer.md)继续拥有固定目录与失败恢复，发布 ID 分配改为更新时间分配。三篇部分取代，继续保持活跃并同步事实。

相关决策：[Shared Widget 中英文内容与缩略图](../../implemented/feature/2026-10-23-shared-widget-localization.md)拥有语言产物、公开引用及语言投影；本记录继续拥有单投稿身份与父游标。应用仅展示双语公开引用齐全的 approved，其余返回最小状态标记；已批准但未完成发布时投影为 pending。

## 曾考虑的替代方案

**普通毫秒时间配合严格大于游标。** 同一毫秒内超过 limit 条记录时，翻页会跳过剩余记录；时钟回退还会使新变化落在游标之前，不能保证同步。

**时间与 ID 组成复合游标。** 能区分已有同时间记录，但增加客户端游标字段，还需保证后续写入不会回到已越过的时间范围。采用全局递增时间以满足单字段游标要求。

**保留双表与批量缓存核对。** 已实现新增发布与缓存清理，但同步成本随缓存大小增长，状态拥有多个存储位置。用户明确要求改成单表状态同步。

## 验证

[后端测试](../../../../backend/src/gallery/gallery.test.ts)的 16 项测试通过。并发插入以未来高位值模拟同毫秒与时钟回退，分页期间同时批准已读取行、删除未读取行，最终合并结果与数据库一致；唯一索引拒绝重复 update_at。测试同时断言发布表及删除字段不存在、非 approved 只有最小标记、旧分页参数与核对接口被拒绝，以及重复操作、鉴权、事务失败、R2 清理与迟到上传的终态。

[导入导出测试](../../../../backend/scripts/gallery-data.node.test.mjs)的 9 项测试通过，使用真实本地 D1/R2 验证 v3 往返、v1/v2 转换、目标状态和游标保留、损坏输入、失败重试及目录锁。旧 schema 中四种生命周期记录经过迁移后保留元数据与资源身份，生成不同 update_at；默认本地开发库已应用迁移。

[GalleryTests](../../../../ios/WidgeeTests/GalleryTests.swift)的 9 项 iPhone 测试通过，覆盖按 ID 更新、移除页游标、旧缓存隔离、重复或倒序响应拒绝、写盘失败、后续页失败、图片清理和已采用资料库保留。签名构建、SwiftLint、iOS 静态检查与 TypeScript 检查通过。

隔离 Worker 浏览器验证复用既有真实模型 QA 投稿的存储副本，迁移后截图和代码仍可读取；Admin 确认删除后列表移除，旧 update_at 请求返回一条新的 deleted 标记，详情与产物均 404。截图和 xcresult 位于忽略的 .playwright-mcp/gallery-delete/。没有新增真实模型调用，没有删除默认开发库中的投稿，未执行生产迁移或部署；旧客户端未提供兼容适配。

## 后果

update_at 是有时间含义的同步版本，不保证完全等于实际发生毫秒；它的正确性依赖所有写入入口遵守原子递增分配。物理清表或用旧备份覆盖在线库仍不能保留客户端游标语义。

单表同步表达最终状态，不提供每一步审核历史。首次同步需要扫描包括删除标记在内的历史行，不能任意清除这些行。备份中的源 update_at 只用于记录，不作为目标游标。

此次替换改变公开响应与资源 ID，旧客户端需升级；生产迁移和部署不由本地实施自动执行。
